# 游戏术语 · 参考图台账 · 怎么给我截图

> 这份文件是**给机器看的字典**：程序里所有"光柱""A框""门禁"的判断，口径都写在这里。
> 也是**给人看的交接**：哪张图代表什么、当时错在哪、正确答案是什么。
>
> 维护方式：`assets/ref/labels.json` 是正式台账（工具读它），本文是它的说明书 + 术语解释。
> 更新日期：2026-11-17

---

## 0. 一句话背景

这套程序要干的事：**看屏幕 → 认出"现在能不能动、地上有什么、该往哪走" → 发出鼠标键盘指令**。
它认错一个概念，就会在完全不该动的地方动（真实事故：**关卡选择页**上被判成战斗，
还给出「向右下移动接近 auto2 掉落光柱（距离 237px）」）。

所以术语必须抠到像素级判据，不能靠"大概长什么样"。

## 1. 术语表（当前理解，括号里是"我据此写进代码的判据"）

| 术语 | 含义 | 代码里的判据 |
|---|---|---|
| **刷图 / 一把图** | 进一张关卡 → 清怪 → 捡东西 → 结算 → 再开一张，循环 | `DecisionEngine` 的状态机 + 再次挑战按钮检测 |
| **掉落光柱（loot beam）** | 地上掉了一件**值得捡的东西**，从物品处竖直升起的一道细长光，颜色代表稀有度 | HSV 颜色白名单 + 高宽比 ≥2.5 + 宽 ≤70px + 白热芯占比 + 连续 2 帧同位置 |
| **白热芯** | 光柱最中心那条近乎纯白的亮线（HDR 过曝），是它区别于彩色技能光效的关键 | `white_core_s_max` / `white_core_v_min` / `white_core_min_ratio` |
| **地面光斑** | 光柱**底部**贴着地面的一小片亮光，位置=物品实际所在 | 光柱 `y` 取的是底部中心，不是几何中心 |
| **地面标签 / 物品名** | 地上那行黄/橙色小字（"Item 1234"），有的游戏靠它显示物品名 | `ground_labels` 检测；与怪物互斥（字不是怪） |
| **A 框 / 拾取提示** | 靠近可交互物时出现的按键提示框（暗黑 4 是屏幕中下"A"） | `aframe` 模板匹配；**铁律：没看到 A 框绝不按 A** |
| **关卡选择 / 异界星图** | 整屏 UI，一堆带名字的发光节点（蛮荒之焰/钢铁炼境/雷鸣废土/混沌终末/伟大虚空/冰封寒渊/幽冥暗域） | 场景门**反例模板** `templates/neg_tli_nether_map.png` |
| **结算 / 再次挑战** | 清完图弹出的结算面板，右下角"再次挑战"按钮 | `rechallenge` ROI 模板/启发式 |
| **背包 / 装备面板** | 整屏 UI，格子+物品 tooltip | 场景门（未标定前靠 fail-closed 拦） |
| **技能轮盘 / 摇杆** | 手机端 HUD：右下圆盘技能键、左下虚拟摇杆 | 场景门**正向模板**该裁这块；也是怪物检测的误报源（被 HUD 排除区抹掉） |
| **门禁（scene gate）** | 每帧先回答"这是不是战斗界面"，答否就**一条指令都不发** | 反例模板 → 技能栏模板 → 都没命中就拦下（未标定不动手） |
| **铁律** | 硬约束：没 A 框不按 A、不停手不盲点、同一位置不连点 | `violations` 记录，仪表盘会报警 |

### 光柱 ≠ 任何发光的东西（本次事故的根因）

用户看到的那张图里**一个光柱都没有**，程序却报了 3 个。逐条列清"长得像但不是"的东西：

| 像但不是 | 为什么容易被误判 | 现在的排除判据 |
|---|---|---|
| **星图节点**（关卡选择页的发光图案） | 有白芯、有 glow、竖直向上 | 高宽比只有 1.4~2.0（光柱 ≥2.5）+ 该页被反例模板整体拦掉 |
| **技能激光 / 光束** | 又细又长、饱和度高 | 白芯校验（技能是纯饱和色）+ 时域确认（技能 1~2 帧就没） |
| **Boss 光环 / 触手 / 冲击波** | 大面积发光、会动 | 高宽比、面积上限、与光柱形状不符 |
| **传送门 / 传送光柱** | **形状几乎和掉落光柱一样**，也是竖直的 | ⚠️ **目前没有判据**，见下面的"待确认问题" |
| **地图上的任务标记光柱** | 同上 | ⚠️ 目前没有判据 |

## 2. 怎么给我截图（这套流程能把"我的理解"变成"程序必须满足的答案"）

目标：**你截的每一张图，都变成一条不可反驳的回归用例**。加一次，永久生效，
以后任何改动让它退步，测试就红。

### 2.1 截图要求

1. **全屏原图**，不要裁剪、不要缩放、不要加滤镜/水印（压缩过的图会让模板失准）。
2. 尽量和实际部署一致：同一台设备、同一分辨率、同一画质设置。
3. 每次至少覆盖这几类（有多少给多少，缺的写"没有"）：

| 类别 | 数量 | 必须标注 |
|---|---|---|
| 战斗（地上有掉落光柱） | 3~5 | 光柱在哪、什么颜色、是不是你要捡的 |
| 战斗（地上没东西） | 2~3 | 确认"这一帧确实没有光柱" |
| 关卡选择 / 地图 | 1~2 | 确认"这页没有任何掉落物" |
| 结算 / 再次挑战 | 1~2 | 按钮位置 |
| 背包 / 装备面板 | 1~2 | — |
| 加载 / 过场黑屏 | 1 | — |

4. **遇到误报就截当前画面**，并写一句"程序说了什么 / 正确应该是什么"。
   这一类最有价值——它直接对应一条要修的 bug。

### 2.2 命名与落盘

```
assets/ref/<游戏>_<场景>_<序号>.jpg     例：tli_nether_map_01.jpg / tli_combat_01.jpg
```

然后在 `assets/ref/labels.json` 里加一条（字段含义见文件顶部 `howto`）：

```json
{
  "file": "assets/ref/tli_combat_03.jpg",
  "game": "火炬之光：无限（手机端录屏）",
  "scene": "战斗 · 异界深处，地上 2 个金色光柱",
  "resolution": [960, 432],
  "strict": true,
  "expect": {"in_game": true, "pillars": 2, "aframe": false, "commands": null},
  "note": "两个金色光柱分别在屏幕左下与右下，底部有光斑，没有 A 框（距离远）"
}
```

- `strict: true` → **必须完全对上**，对不上就是 bug（CI 会红）。
- `strict: false` → 已知缺口，只打印差异不拦（等标定完再转 true）。
- `expect` 里只写你**确定**的字段，不确定写 `null`（不检查）。
  可写：`in_game` / `pillars` / `aframe` / `ground_labels` / `monsters` / `commands`。

### 2.3 我这边的动作

```bash
python tools/ref_check.py          # 逐条对比：标答 vs 实测，列出差异
python tools/ref_check.py -v       # 附带备注
```

输出长这样（真实输出，就是这次修完的状态）：

```
[OK  ] tli_nether_map_01.jpg   异界 · 关卡选择（星图）
       门禁=negative:neg_tli_nether_map.png (模板 0.00 / 反例 1.00)  光柱=0  A框=False  标签=0  怪=0  指令=0
[GAP ] tli_combat_01.jpg       战斗 · 异界深处（技能轮盘 + 摇杆）
       门禁=unmatched (模板 0.15 / 反例 0.46)  光柱=1['pink']  ...  指令=0
       ✗ in_game: 标答=True 实测=False
```

`GAP` 不是通过，是"还没标定好"。剩下要做的事会被这张表直接点名。

| 图 | 场景 | 标答 | 状态 |
|---|---|---|---|
| `tli_nether_map_01.jpg` | 异界·关卡选择（星图） | 非战斗 / 0 光柱 / 0 指令 | ✅ 已对上（反例模板 1.00 拦下） |
| `d4_charpanel_01.jpg` | 战斗中打开角色面板（右半屏被挡） | 非战斗 / 0 指令 | ✅ 已对上（反例模板 0.96 拦下；普通战斗帧 ≤0.38） |
| `real_hud_boss.png` | 主线 Boss 战（PC，全 HUD） | 战斗 / 0 光柱（有光照特效） | ✅ 已对上（技能栏模板 0.93） |
| `tli_combat_01.jpg` | 战斗·异界深处 | 战斗 | ⚠️ 缺口：手机端 HUD 没模板覆盖 → 被 fail-closed 拦下 |
| `tli_combat_02.jpg` | 战斗·Boss 光环满屏特效 | 战斗 | ⚠️ 同上 |

补齐最后两条（手机端战斗）的方法（5 分钟）：

```bash
# 1. 从战斗截图裁一块"只有战斗才出现"的 HUD 部件（右下技能轮盘外圈 / 摇杆环 / 血球）
python tools/make_template.py --src assets/ref/tli_combat_01.jpg \
    --rect 690,190,960,410 --out templates/skillbar_tli_mobile.png \
    --check "assets/ref/tli_combat_*.jpg"

# 2. 看它给的分数：正向模板要在**所有**战斗截图上 ≥0.6 才算合格
# 3. 把 labels.json 里对应条目的 strict 改成 true
```

> 注意：裁模板要选**位置固定、不受技能特效/冷却/血量影响**的部件。
> 图标本身会变色、会转 CD，裁进去就等于把模板焊死在某一个瞬间。

## 4. 待确认问题（下次对话请直接回答，我据此改判据）

1. **传送门 / 传送光柱**长什么样？和掉落光柱怎么一眼区分？（颜色？底部有没有光斑？有没有文字？）
2. 掉落光柱**会不会移动**（比如物品被推走、跟随玩家）？还是永远钉在地上？
3. 你的**稀有度配色**：白/蓝/黄/暗金/绿套，哪些是"值得走过去捡"的？现在代码只认 `gold`/`pink`。
4. 光柱**头顶有没有物品名文字**？间距大概多少？（有的话可以拿它做二次校验）
5. 手机端（火炬之光无限）的 HUD 里，哪一块是**任何战斗画面都一定在、且不会变**的？
   （我建议右下技能轮盘的外圈框，或左下摇杆的圆环）
6. 除了"异界星图"，还有哪些整屏 UI 会导致误操作？（仓库、商店、天赋、成就……）
   每一个都值得一条反例模板。
