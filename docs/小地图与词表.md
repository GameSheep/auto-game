# 运行时只要四件事：光柱、地图位置、物品名、A 框

对话里定稿的运行时范围。这份文档只讲"这四件事各自由谁负责、怎么验、边界在哪"。

| 要的东西 | 模块 | 输入 | 输出 |
|---|---|---|---|
| 掉落光柱位置 | `vision/detector.py` | 一帧 BGR | `Pillar(x, y, cx, cy, w, h, color)` |
| 人物在整张地图的位置 | `vision/minimap.py` | 小地图裁片 + 离线底图 | `MapPos(x, y, u, v, score)` |
| 掉落物名称 | `vision/nametags.py` | 光柱 + 字条词表 | `(名字, 分数)` 或 `None` |
| A 标记 → 按键 | `vision/detector.py` + `decision/fsm.py` | 一帧 BGR | `AFrame(x, y, w, h, score)` |

前两件是"是什么/在哪"，后两件是"该不该动"。**没有任何一件依赖大模型**，全是
OpenCV + 少量标定参数，这是这套东西能在 RK3566 上以 1Hz 跑下去的原因。

## 一、光柱（已有）

HSV 阈值 + 轮廓 + 细高条状 + 白芯校验 + 时域确认（跨帧持续出现才算）。
`config.yaml` 里 `vision.hsv.<颜色>` 定阈值，`whitelist_colors` 按稀有度筛。

要点：光柱检测给的是**屏幕坐标**，决策层据此点地面走过去；它不关心那是什么东西。
"要不要捡"由第 3 件的名字决定。

## 二、小地图定位（新增）

小地图是**随人物滚动**的局部视图，中心那张半透明的是整图 —— 所以"我在哪"不能靠
找箭头（箭头恒在中心），只能靠**把小地图这块地形和离线底图对齐**。

```
小地图裁片(245x245) ──┐
                      ├─ 1:1 匹配 → 峰值 + 边缘复核 → 底图坐标 → (u,v)
底图按 zoom 缩小一次 ──┘
```

### 标定（只做一次，换图/换分辨率才重做）

```bash
# 1. 扫 zoom，报告最佳档位
python tools/map_probe.py --map "整图.png" --frame 截图.png --roi 0,55,245,245 --sweep

# 2. 用定下来的 zoom 正式跑，看红叉落点对不对（输出标注图）
python tools/map_probe.py --map "整图.png" --frame 截图.png --roi 0,55,245,245 \
    --zoom 0.12 --out debug_map_probe.png

# 3. 一批截图看命中率（人物走过地图各处）
python tools/map_probe.py --map "整图.png" --dir assets/frames --roi 0,55,245,245 --zoom 0.12
```

`--sweep` 的输出长这样，最佳档位会**明显高于邻居**（下面第 2 名低 0.24）：

```
zoom=0.250  score=0.818
zoom=0.260  score=0.574
zoom=0.240  score=0.557
```

如果最佳档只比邻居高一点点，说明那片地形太"平"（到处长得都差不多），换个有地标的位置重标。

### 两条通过线，缺一不可

| 参数 | 管什么 | 调它的信号 |
|---|---|---|
| `locate_threshold`（0.55） | 灰度 NCC，主分数 | 真命中普遍低于 0.4 → 降；误报多 → 升 |
| `edge_threshold`（0.25） | 边缘图复核 | 分数很高但点落偏几十像素 → 升 |

**为什么两条都要**：平滑地形上 `TM_CCOEFF_NORMED` 会出现大片高分区（"哪都像"），
最高峰经常偏十几到几十像素，分数还很好看。边缘图能分辨"纹理方向对不对"，是唯一的
结构证据。这跟 A 框那次"11/11 全是误报"是同一个教训：分数是必要条件，不是充分条件。

### 会自己拒绝的三件事

- **裁片是纯色**（黑屏/被面板盖住/小地图没加载）→ 直接不给坐标。零方差的 NCC 处处 1.0。
- **一帧跳几百像素** → 先不采信，连续 `jump_confirm` 帧都这么说才认（真传送/切图）。
- **连续 3 帧认不出** → 丢掉上一帧位置，不再在旧窗口里打转。

### 边界

- 小地图**随视角旋转**的游戏，这套平移搜索会失效，要先转正（或用 ORB）。
- 底图必须是**同款地图**、**无 HUD**、**未缩放**；换图忘了换底图 = 分数永远是 0.3 上下。
- 精度上限是 `1/zoom` 个底图像素。zoom=0.12 时 1 个小地图像素 ≈ 8 个底图像素，
  知道"在哪个区"够用，做厘米级寻路不够。

## 三、物品名（新增）

固定词表 → 每个名字裁一张字条 → NCC 匹配。**不走 OCR**：手机画面里名字只有
10~14px 高，tesseract 中文误识率不低，认错就是捡错东西。

详见 `templates/names/README.md`（裁法、阈值怎么定、边界）。

行为约定（这条很重要）：

| 配置 | 认出名字 | 没认出 |
|---|---|---|
| `whitelist` 有值 | 命中白名单才捡 | **不捡** |
| `whitelist` 为空 | 都捡，`label` 填名字 | 都捡，`label` 空 |

也就是说，"只捡某几样"这件事靠的是**认不出来就不捡**，而不是"猜一个最像的"。

## 四、A 框 → 按键（已有）

真实 A 提示是"暗底 + 白色字形"。只按形状判定时，真实帧上 11 个候选**全是误报**
（伤害数字、技能图标、Boss 特效）；加上结构校验后 100 帧只剩 1 个命中，人工核验是真的。

配套的三道闸：
1. **邻近目标**：A 框必须挨着当前目标才按（防止对着别的可交互物按 A）。
2. **150ms 防闪烁**：A 框闪现一帧不按。
3. **不变量**：`picks <= a_taps`，没按过键就不许记"捡到了"。

## 顺手修掉的一个坑：中文路径

`cv2.imread` 在 Windows 上遇到中文路径**返回 None 且不报错**。而这条链路上中文是
必然的（物品名就是中文，字条文件名就是物品名）。所以读图统一走
`autogame/vision/imgio.py`（`np.fromfile + imdecode`，只吃字节）。
如果你自己写脚本读图，别用 `cv2.imread`。
