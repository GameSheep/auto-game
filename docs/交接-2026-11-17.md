## 1. 项目是什么

`autogame`：全自动刷图机器人。链路是

```
采集（摄像头/HDMI/截屏） → 检测（Detector） → 决策（FSM + 恢复阶梯 + VLM/LLM 顾问）
   → 指令（Command 协议） → 执行（RP2040 HID / 树莓派 GPIO / DryRun）
```

落地形态：**RK3566 小主机**跑服务端 + 摄像头看屏幕 + HID 板子发鼠标键盘。
配置页在 `http://<设备IP>:8765/settings`，仪表盘在 `/`，审查页在 `/review`。

铁律（不可绕过，测试会盯）：
1. 场景门说"不是战斗界面"→ **一条指令都不发**；
2. 没看到 A 框 → 绝不按拾取键；
3. 同一个位置不连续盲点；不停手不盲点。

### 阶段 C：用户拿着配置页截图报的"离谱"

原话：*"这个图里根本没有掉落光柱……明明是关卡选择页面，怎么还显示意图 向右下移动接近 auto2 掉落光柱 距离 237px"*。

排查链条（这次最有价值的收获）：

1. **场景门一直是"常开"的**。`_check_scene_gate` 顺序是 技能栏模板 → Q 字母锚点 → 红血球。
   技能栏模板在手机端只有 0.25（模板是暗黑4 的），于是落到 Q 字母锚点——而
   `templates/q_letter.png` **实际是一块技能图标的角落，不是 Q**。实测：
   - 8 张真实截图里 7 张给出 0.77~0.99，**唯一低的那张（背包 0.60）是它自己运气不好**；
   - 用形状 IoU、全分辨率匹配、OTSU 各种加固都救不回来（地图页 IoU 0.889）。
   → 结论：这不是"阈值没调好"，是**模板内容错了**。直接删掉这条锚点。
2. **光柱判据太松**。`pillar_min_aspect` 默认 1.1，而那张星图上的发光节点高宽比
   1.4~2.0（还带白芯），于是 3 个节点被当成光柱。实测真实光柱是 3~8（模拟器 7.9）。
   → 下限提到 **2.5**，并在 `config.py` 里把"为什么是 2.5"写清楚。
3. **意图是上一帧的残留**。门禁拦截时 `_tick_gated` 直接 return，`last_intent` 没清，
   审查页/仪表盘就把上一帧的"接近 auto2 光柱"挂在结算页/地图页上。
   → 拦截时写入"非战斗界面：本帧不决策、不点击"。
4. **门禁应该反例优先 + 兜底拦下**。新增：
   - `scene_gate.negative_templates`（`templates/neg_*.png` 自动加载）：整屏 UI 的静态裁块，
     命中即判非战斗——这是唯一对"菜单/面板"可靠的判据；
   - `scene_gate.fail_closed`（默认 true）：一个正向锚点都没命中 → 判非战斗（未标定不动手）；
   - `diag.gate_reason`：`negative:<模板名>` / `skillbar` / `red_orb` / `unmatched` / `no_template`，
     配置页「相机」与审查页都会显示，不再"静默放行"。
5. **参考图台账**：`assets/ref/labels.json` + `assets/ref/*.jpg`，把人工标定过的正确答案
   变成回归用例（`tests/test_ref_labels.py` 跑 strict 条目）。

修完的门禁行为（真实数据）：

```
异界星图（960x432）   门禁=negative:neg_tli_nether_map.png (反例 1.00) → 光柱 0 / 指令 0
暗黑4 角色面板        门禁=negative:neg_d4_charpanel.png  (反例 0.96)  → 指令 0
主线 Boss（1280x720） 门禁=skillbar (0.93)                            → 光柱 0 / 指令 2
手机端战斗（960x432） 门禁=unmatched (模板 0.15 / 反例 0.46)            → 被拦（未标定）
```

审查页为了能继续"看清感知层想干什么"，加了 `--gate-unmatched pass`
（离线分析模式：未标定的帧当战斗跑，页头有黄条提示，生产默认仍是 hold）。

## 3. 现在的门禁到底怎么判（照着改别再猜）

```
每帧：
  1. 反例模板命中（≥0.80）  → 非战斗（确定的菜单/面板，任何时候都拦）
  2. 技能栏模板命中（≥0.60）→ 战斗
  3. 什么都没命中 → fail_closed=true  → 拦下（reason=unmatched，"未标定"）
                  → fail_closed=false → 放行（老行为）
```

**只有"能拿出证据"的锚点才允许放行**。这次顺手删掉的两条兜底判据
（`q_letter.png` 键位字母、红血球色斑）都属于"给不了证据却敢放行"：
- `q_letter.png` 实际是技能图标的一块角落 → 8 张真实截图里 7 张给 0.77~0.99；
- 红血球色斑 → 在星图/装备面板/录像里到处命中（星图上那块红色节点就够面积）。

删掉之后的行为变化：装备面板、`real_beamlike_tentacles.png` 从"放行"变成"拦下"。
前者本来就该拦；后者是真正的战斗画面，但它的技能栏和 `skillbar*.png` 不同源
（模板 0.18）——这正是"必须为自己的游戏标定一次"的例子，不是回归。

正向模板 = `templates/gate_pos_*.png`（多张，任一命中即可；旧名 `skillbar*.png` 仍认）
反例模板 = `templates/gate_neg_*.png`（多张，任一命中即拦；旧名 `neg_*.png` 仍认）

> 11-18 起模板按游戏分目录：`profiles/<id>/templates/`，由 `--profile` 决定。
> 见 `profiles/README.md` 与根 README 的「换游戏」一节。

**代价（必须知道）**：手机端 960x432 的两段录像在标定前**全部被判"未标定"拦下**，
所以 `assets/frames_replay/report.html` 里的指令数会掉到 0。
这不是退步，是以前那 290 条指令本来就跑在一个"永远放行"的假门禁上。
（11-18 已补齐 `profiles/tli_phone960` 的正例锚点与星图反例，这两段录像现在能正常放行；
真正的新游戏仍要走一遍标定，见 `profiles/README.md`。）
