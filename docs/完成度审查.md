## 0. 审查基准说明

没有发现凭空捏造的功能项**；但有 3 处状态标注偏高、若干处数字漂移。

## 3. 做得扎实的部分（不是客套）

1. **安全铁律真的被代码强制**：`picks ≤ a_taps`、无 A框不按 A，在模拟闭环、100 张真实帧、
   8 张实机截图回放中实测 `blind_tap_violations = 0`。这是最容易造假的地方，实测站得住。
2. **测试不是摆设**：149 个用例含真实 uvicorn 起服的端到端闭环、硬件报文字节级断言、
   真实帧回归、fuzz 加固、性能守卫。121 秒全绿，可复现。
3. **失败路径考虑得比一般脚本周全**：撞墙帧差检测、走位超时拉黑、A框闪烁误检不计成功、
   拾取复核冷却（连按捡垃圾的真实时序 bug 已修）。
4. **降级设计**：dxcam→mss、OCR null→tesseract→paddle、执行器四后端、LLM 可选，
   缺依赖不崩（实测 pytesseract/smbus2 未装，系统照常跑 dryrun）。
5. **审计与可观测**：JSONL 事件日志 + MJPEG 仪表盘 + 图片审查页（图在上、命令在下），
   运维视角是完整闭环的。

## 4. 关键缺口（按优先级）

### P0-1　真机端到端零验证（一票否决项）
`logs/events.jsonl` 里没有任何执行器 op 记录，`firmware/` 下没有 `.pio` / `.uf2` 构建产物，
测试中的执行器全是 mock / 字节级断言。**这个项目从未有一次"真实按键打到真实游戏里"的记录。**
真实环境会引入现在完全没覆盖的变量：游戏反作弊/输入时序、窗口失焦、多显示器 DPI、
绝对鼠标坐标映射偏差、舵机按压回弹、网络抖动下的帧丢弃。

> 建议：先做 30 分钟最小真机闭环（dxcam 采集 + 局域网 + RP2040 按 A），把 events.jsonl 里的真实 op 记录补上。

### P0-2　标定资产缺失，核心白名单铁律默认失效
- `templates/aframe.png` **不存在**（只有 `aframe_tli.png` 变体），`config.yaml` 里
  `vision.aframe.template` 是注释掉的 → 当前靠颜色 + 镂空率兜底，精度低于模板匹配。
- `vision.whitelist: []` 为空 → 需求 C3"只捡白名单装备"**默认不生效**，实际是"所有光柱都捡"。
- `vision.hsv` 是通用默认值，未针对当前游戏版本/画质标定。
- 更矛盾的是 `.gitignore` 里有 `/templates/*.png`，等于把最关键的标定产物排除在版本管理外。

> 建议：补一份当前版本的标定产物（aframe.png / rechallenge.png / HSV 实测值 / whitelist），
> 并把模板纳入版本管理（或改为标定脚本可再生成）。

### P1-1　UI 场景自动化（H11）实际空转
实测 `trade_buy`：`skip_panel_check` → `skip_button` → 5 步零命令。`templates/ui/` 目录不存在。
需求清单标 ✅，README 有小字说明"需先放模板"，但**功能实际不可用**，应降级为
"框架就绪，待标定资产"。

### P1-2　硬件四后端全部未实测
- RP2040 固件 229 行从未编译（无构建产物）；
- `pca9685` 只测过 mock 总线；
- `rpi5_hidg` 只在测试路径里跑过；
- `pyserial`/`smbus2`/`pytesseract`/`paddleocr` 在当前 venv 均未安装（延迟导入，不会崩，但也没验证过）。
- 需求 D6"混合方案并行（机械按A + HID 鼠标）"实为**单后端可选**，不支持同时挂两个后端 ——
  属标注偏高。

### P1-3　工程化缺失
无 `.git`（无版本历史、无回滚、无 diff 审查）、无 CI、`requirements.txt` 未锁版本、
pytest 无覆盖率门槛。`pytest.ini` 只有 4 行。

### P2-2　其他
