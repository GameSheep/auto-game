# 8. 自主性升级（2026-11-16 第三轮）

用户要求："提高 LLM 和视觉模型调用，作为搬砖机器人要有更高智能，绝对不能卡壳。"
这一轮不加新功能面，只补**长期无人值守**这一维（原来只有单目标级别的"放弃+拉黑"）。

## 8.1 之前缺的是什么

原来的"不卡死"只覆盖单目标：走位 8s 超时 → 放弃拉黑 → 继续扫描。但真实搬砖会卡在
**规则覆盖不到的地方**，而且每种都会让机器人"安静地站着"：

| 卡法 | 原来的表现 |
|---|---|
| 撞在墙角/被地形挡住 | 目标拉黑后换个目标，仍在原地撞 |
| 房间走完但没有掉落 | 站着等刷新（explore 默认关） |
| 弹窗/菜单/结算界面没退出 | 场景门拦截 → **零命令**，永久静止 |
| 游戏假死/窗口失焦 | 画面不动，无任何判据 |
| 代理掉线 | 服务端无帧，但仪表盘仍显示"运行中" |
| 代理重启导致帧时间戳回退 | 所有超时判据算出负数 → 逻辑错乱 |

## 8.2 现在的结构（三层）

1. **看门狗**（`decision/recovery.py::ProgressMonitor`）：frozen / idle / stalled / gated / loading
   五态判定，全部基于帧时间戳；`frozen` 还要求"我们确实发过动作却没反应"，
   避免把"站着没事干"误判成卡死。
2. **恢复阶梯**（`RecoveryLadder`）：重定位 → 四向探路 → ESC → 脱困键 → 重新聚焦 →
   八向脱困 → 重开关卡 → VLM → LLM → 新一轮（降速 + 告警，`max_cycles=0` 无限重试）。
3. **模型顾问**：VLM 看截图给动作（白名单 + 坐标钳制 + 每分钟预算 + 熔断 + 后台线程），
   LLM 看摘要给策略（explore/reset_stage/wait/panic）。两者都只是"顾问"，不能按拾取键。

另外补了程序自身的健壮性：帧流看门狗（10s 无帧告警、恢复后消警，**无画面绝不盲动**）、
时间戳回退重基准、`/api/autonomy` 排障接口、仪表盘「自主恢复」面板。

## 8.3 一个真实的设计 bug（这轮发现并修掉）

`pickup_key: a` 与 WASD 左移同键。原来的 `explore` 直接按方向键，**一探索就等于盲捡**。
端到端测试立刻抓到：模拟世界 `blind_a_press` 从 0 变成 17。
修法两层：
- 探索/脱困改为**点地面**（mouse_click 模式），从根上不碰键盘；
- `_emit_move_keys` 闸门：任何走位按键只要等于拾取键就拦截并计入 `blind_tap_violations`。
现在三种卡壳场景 + 全量 199 用例里，盲按恒为 0。

## 9.2 这一轮发现并修掉的真实 bug

1. **"取消"会把补丁打上。** 确认框的选项就是 `["确认","取消"]`，先比选项文本时
   "取消"命中第 2 个选项 → 被当成"选了取消" → 拿着 payload 去 apply。
   人越想取消，改动越会被打上。改成"确认/取消/编号"先于选项文本。
2. **观察模式把引擎停掉了。** `_hard_stop` 对 observe 也调 `fsm.stop()`，
   于是"观察"实际上什么都不观察。拆成 `_release(stop_engine=...)`。
3. **暂停到点不会自己接着跑。** 模式恢复到 COOP/FPS 状态还是 PAUSED，没人点亮引擎。
   模式管理器加 `on_change` 回调（锁外通知），到点自动 `_engine_start()`。
4. **页面按钮绕过模式。** `hub.control("start")` 只动 FSM，模式还停在暂停，
   表现是"显示在跑、动作全被拦"的假运行。改成两者一起动。
5. **改完规则没重载。** 补丁写完文件，`Arbiter` 还是启动时那套 —— 下次重启才生效。
   现在写完当场 `reload_rules()`；配置补丁也当场 `apply_patch` 并报告需重启字段。
6. **学习完不生效、还会被旧基线误判。** 换代后规则没重载、体检基线还是旧配方的，
   于是新代上线第一分钟就报"变慢"然后被回滚。加 `evolve.set_generation_hook`。
7. **FSM 事件进不了现场记录。** 只在开了 `event_log` 时才挂回调，关掉审计日志的机器上，
   "急停/卡死/进恢复"这些最该被解释的事全都看不到。
8. **过期提问被当成"没有在等确认的事"。** 用户明明看着问题框回答，得到的却是
   "现在没有在等确认的事"。过期现在会明确说"过去太久了，重新问"。
9. **规则补丁"覆盖"是空操作。** `PatchStore._build_rule` 里 `rules = [...]`
   只重绑了局部变量，`doc["rules"]` 还指着原列表 —— 补丁账本记成已应用、校验还说
   "原有规则都在"，文件一个字没变。经验晋升靠这条路径改门槛，表现就是"学了但没变"。
   现在写回 `doc["rules"]`，并有用例钉住（`test_rule_patch_overwrites_an_existing_rule_for_real`）。
10. **stall 规则限流用 `0.0` 当"从没拦过"。** 帧时间从 0 开始，于是开跑前 10 秒
    规则被白白抑制。改成 `None` 哨兵。
11. **RP2040 的鼠标坐标从来没换算过（真机上鼠标等于全废）。** 固件的鼠标描述符
    声明的是绝对坐标、Logical Max 32767，它对收到的数字不做任何换算；而主机的
    `RP2040Executor` 把**像素坐标直接发过去**。1280×720 画面里点 (640,360)，
    固件收到 640，光标落在屏幕 2% 处。hidg 后端早就用 `build_abs_mouse_report`
    做了归一化，RP2040 这条路径漏了 —— 而两边日志都显示"下发成功"。
    现有用例 `test_rp2040_json_framing` 当初是按"像素直发"写的，等于把这个错误
    固化成了规格。现在换算统一放在 `_write`（唯一出口），并有用例钉住
    "同一像素坐标在两个后端落到同一位置"。
12. **`runtime_overlay_path("")` 直接抛 `ValueError`。** `Path("")` 是 `Path(".")`，
    对它调 `with_name` 会炸。这条路径会在"经验想把配置写进 overlay"时被走到，
    表现是"配置补丁写不进去"，原因却是一句 `WindowsPath('.') has an empty name`。
    现在退到数据根下的 `config.yaml`，既不抛异常，也不会在 cwd 里凭空多出一份
    永远读不到的覆盖文件。

## 9.4 经验长成规则：从"记下来"到"会用了"

上一轮的经验闭环只写到手册：候选晋升后多一条给人看的文字，程序的行为一点没变。
这一轮把它接到规则上 —— 学到的经验下一次**当场**改变动作。

| 连接处 | 之前 | 现在 |
|---|---|---|
| 规则语言的事实 | 只有画面类（pillars/monsters/…） | 加 `repeat` / `repeat_key` / `recoveries` / `picks_delta` / `no_progress_for` / `intent_churn` / `cmds`，全部来自 probe 每 tick 真的产出的字段 |
| probe 产出 | 没有 `repeat`，也没有"最近一分钟进恢复几次" | `_arb_probe` 用 `monitor.recent_repeat`（与体检同一份实现）+ `_recovery_ts` 现算 |
| 求值时机 | 只有 `idle`（FSM 停手 ≥1.5s） | 加 `trigger: stall`：卡住那会儿 FSM 一点都不闲，等停手等于永不生效 |
| 救场限流 | 硬编码 10 秒常量 | `arbiter.rule_stall_gap_s` 可调：不同游戏"卡住"能持续的时间差一个量级 |
| 晋升 | 只写 `lesson` | 写 `lesson` + `rule`，规则走 `PatchStore`（预览/校验/原件/可回滚），写完 `reload_rules()` |
| 页面 | 只有"记进手册"按钮 | 候选上直接显示"会写成规则：当 … → …"，写不出的显示原因 |

四条硬规矩（都是为了"不许假装学会"）：

1. **条件只准引用真会产出的事实。** 引用缺席字段的规则能过校验、能写进 rules.yaml，
   然后一次都不命中 —— 页面上却显示"已经学会"。
2. **缺字段必须求值成 unknown。** 监督层关掉时 `picks_delta` 这一组**不出现**，不填 0；
   填 0 会让 `picks_delta == 0` 在"根本没在测"的时候命中，规则去治错病。
3. **门槛比告警线更早。** 体检在重复 12 次时告警，规则取 `0.75N`（约 9 次）介入。
4. **写不出规则的，改配置，不硬编动作。** `slow` / `model_burn` 这一类治的是"负担"，
   而动作清单里只有 9 个游戏内行为（走开/打/捡/等/导航/重挑/重置/ESC），没有
   "降级""少问模型"这类动作 —— 硬写规则只会在慢的时候让角色随便走两步。
   它们改成生成**配置补丁**：`slow` → `decision.tick_hz = 0.5`，
   `model_burn` → `decision.arbiter.cooldown_s = 60`，走 `PatchStore` 的 config 路径
   （写 `config.runtime.yaml`，删掉即回滚），晋升后当场 `apply_patch` 到内存。
   候选上 `kind` 会写 `lesson+config`，页面显示"会改配置：decision.tick_hz = 0.5"。

## 9.5 上真机前自检：把"静默失效"变成"上机前就看见"

`doctor.py` 回答的是"这台机器能不能**起来**"（升级闸门）；真机上真正难查的是
**"起来了但动作全废"**，两条路完全不同，所以新加了 `preflight.py`。

| 检查 | 真机上的意义 | 不过时 |
|---|---|---|
| 执行器探活 | `ping` 回 `{"ok":true,"fw":"1.1.0"}` 才算对面真是这块固件 | fail |
| 固件版本 | 回 `unknown op` = 是这套固件但太旧，**要重刷**（与"对面不是这板子"是两种修法） | fail |
| 能松手 | 发一次 `stop_all`（只松不按，最安全的探针） | fail |
| 动作闸门 | 模式/闸门任一关着，上机也一步不走 | fail |
| 采集在流 | 最近一帧超过 3 秒 = 瞎子 | fail |
| 画面尺寸 | 帧 1280×720 vs `screen_w` 1920×1080 → 点中心落到 (960,540) | fail |
| 采集区域偏移 | `capture.region` 的 left/top ≠ 0，而下发坐标没加偏移 | fail |
| 角色位置 | 坐标出画面 = 标定参考分辨率不对 | fail（缺角色只 warn） |
| 采集/决策频率 | 决策 2Hz 高于采集 0.5fps = 同一个画面被决策多次 | warn |

三条设计上的取舍：

- **结论是三档**（`ok` / `dry` / `blocked`）。`dry` 是刻意保留的中间态：
  用 dryrun 在真机环境跑通链路完全合理，算成失败会逼人说谎；但它绝不能显示成
  `ok`，那正是"以为在跑"的来源。探活被跳过时文案是"没验证硬件"，与
  "确定不会动手"分开说。
- **服务在跑时不做串口探活。** 插一句 `ping` 会抢走正在下发命令的回显，
  既可能把好固件误判成故障，也会打乱那条命令的 ack。此时报 `skip`，提示先暂停。
- **`probe()` 默认实现返回失败而不是 True。** 新加的后端忘了实现探活，
  自检会拦下来说"这个后端没有探活"，不会默默放行。

`tools/e2e_real_screen.py` 也跟着改了：`--backend` 可选真后端（默认仍 dryrun），
抓帧后立刻比对帧尺寸与 `screen_w/h`，不一致就拒绝开始（`--yes` 可强过）；
真后端会先提醒"确认游戏窗口在前台"；跑完再输出一段上机自检结论。

## 9.7 行为伪装：从"加随机数"到"伪造人类的约束"

用户贴了一份检测维度：**鼠标移动轨迹天差地别**、**操作间隔高度标准化**，
后来又补了一条 —— **代码里根本没有"高频连按"这个概念**（点完就下一步）。

这三条的共同点是：**加随机数不解决问题**。反作弊看的不是"有没有抖动"，
而是"这条序列符不符合人类的生成机制"。

| 层 | 旧做法 | 问题 | 现在 |
|---|---|---|---|
| 轨迹 | WindMouse（公开算法） | 有现成指纹：步长自相关高、横向偏移≈线性、clip 造成等幅平台 | 伪造运动学不变量：Fitts 律时长、2/3 幂律（弯处减速）、亚运动多峰、σ∝v 噪声、高斯落点 |
| 节奏 | 固定节拍 × U(0.9,1.1) | ACF(lag>1) 掉到 0（白噪声），DFA≈0.5；**帧驱动量化**让 fps=2 时间隔只剩 500/1000ms 两个值 | `Rhythm`（双态 × 1/f × 对数正态 × 长尾，软下界）+ 亚帧打散 + 下界随机化 |
| 连按 | 无（每个动作孤立单次） | 簇长恒为 1，本身就一眼假 | `Mash`：簇长重尾、第一 gap 最长、越按越快、卡壳、按压更短、成簇出现、有预算 |

三个关键坑（都写进注释了）：

1. **弯曲不能放中段**。单一贝塞尔曲率峰在中段，而中段最快 → 曲率-速度正相关，
   和 2/3 幂律反号，回归一下就被识破。改成分段折线 + Catmull-Rom。
2. **dt 不能独立抖动**。位置序列已编码速度剖面，dt 再叠随机数会把位置和时间脱钩，
   算出假速度峰（实测 3 → 11）。
3. **间隔标准化的根是帧量化，不是数字整齐**。`capture.fps=2` → 500ms 栅格，
   "点击→再点击"只可能 500/1000ms。必须把动作时刻从帧边界挪开（`action_desync_ms`，
   并把延迟顺延到下一拍），否则加多少随机间隔都治不了。
4. **兴奋度必须均值回复**。第一版写成纯衰减 + 噪声，长期均值是 0 ——
   跑十几分钟连按会悄悄消失，日志里看不出原因，只看到"越跑越呆"。

量化（`tools/behavior_audit.py`，14 项全部落在人类参考带内）：

```
指标                旧          新        人类参考
曲率-速度斜率        -0.079     -0.325    -0.33
间隔取值数             2          634      ≈800
锁相 R              1.00        0.25      0~0.35
DFA α               0.59        0.82      0.65~1.10
簇长均值              1.0        4.9       3~9
连按时间占比          0.00       0.25      0.10~0.40
```

**边界（必须说清）**：这些只提高纯统计模型的门槛。行为数据攒够触发人工复核时，
"摄像头看屏 → 程序判断 → 机械臂执行"这套结构瞒不住。它是降低短期风险的手段，
不是安全方案。

## 9.8 仍然缺的（诚实说明）

1. **真机 + 真游戏**：现在有了 `preflight` 和 `e2e_real_screen --backend`，
   能在上机前把"静默失效"拦掉；但"对着真实游戏窗口连续跑 30 分钟、看它能不能
   真的刷完一圈"这一关，仍然必须在有硬件和游戏的地方过。代码侧能做的已经做完：
   坐标换算、探活、尺寸一致性、松手检查都有用例。
2. **sherpa 模型未装**：语音服务端识别/合成只用假模块验证了调用形状，
   真模型的中文识别率没有数据；默认路径是浏览器识别，不受影响。
3. **经验规则的覆盖面**：`repeat` / `recovery_spin` 生成规则，`slow` / `model_burn`
   生成配置补丁。仍有一类结论没有归宿 —— 体检报"没进展"但既不是卡住也不是空转时，
   现在的模板里没有对应项，只会被 `_judge` 记成日志。要补得先确定它该改动作还是改参数。
4. **代码补丁（对话第三阶段）**：不做，改代码走 `upgrade` 整包换代。
   配置里也刻意没有 `allow_code` 开关 —— 一个设了也不生效的开关比没有更误导。

用户问的是"现在对游戏支持到什么程度、能不能上真机"。这一节不给总体百分比，

## 10.1 逐环节（目标：火炬之光：无限 PC 端）

## 10.2 真实帧标答的覆盖偏差（这条容易误判）

`assets/ref/labels.json` + `profiles/tli_phone960/labels.json` 共 8 条 strict 标答，
全部通过 —— 但它们验证的是 **TLI 手机端 960×432 录屏** 和 暗黑4 面板。
**没有一条"PC 端 1280×720 战斗画面里怪/掉落各几个"的标答**，而 PC 才是要真跑的那套。
场景门模板是 PC 的，拾取/怪物判据却是手机录屏调出来的 —— 上机第一件事应该是补这条标答。

## 10.3 本轮修掉的两个"上机才发作"的问题

1. **缺 pyserial 只说 `No module named 'serial'`**。真机上分不清"没装"和"装错解释器"。
   现在构造时抛带修法的 `RuntimeError`（装什么、串口号去哪看、三种常见原因），
   pca9685 缺 `smbus2` 同理。
2. **`preflight` 把"后端起不来"退化成"没有运行中的执行器，跳过"**。
   `build_executor` 抛的异常被吞进一个没人读的变量，结论变成一句无害的 skip，
   而真实原因是串口号错/缺包 —— 这正是自检最该拦的东西。现在是一条 fail，
   并新增**离线也跑**的「后端依赖 / 采集依赖」检查（不碰硬件就能查）。

## 10.4 性能：32.6ms 已过期，而"守卫必红"是降频不是退化

`test_perf_guard_detector_720p` 的注释还写着基准 ~40ms，实测（本机、冷却后）
整帧 40~70ms；涨的是这三样：反例模板匹配（10 张，其中 2 张 250×175）、
血条锚定的怪物检测、地面标签检测。

**但"负载高时 145~437ms"不是代码问题，是这台机器在降频。** 同进程连续跑：
第 1 轮 52ms → 第 2 轮 160ms，同时 `psutil.cpu_freq()` 从 2600MHz 掉到 1496MHz；
空闲 20 秒也不恢复。全量测试要跑 6 分钟，所以这两条守卫在整套里**必然红**、
单独跑却绿。一条"总是红"的守卫等于没有，还会教人忽略它 —— 本项目已经吃过一次
静默失效的亏，这次是反过来的（噪音失效）。

改法：预算按**标定工作量**缩放（`_budget_for_machine()`）。标定是一段固定尺寸的
模板匹配；机器降频会同时拖慢标定和检测，代码退化只会拖慢检测。所以：
标定快 → 预算 90ms（不放宽）；标定慢 3 倍 → 预算 270ms（降频时不误报）；
代码真退化 → 标定不变 → 照样红。策略本身有单测钉住（`test_perf_budget_scales_...`）。

真机意义不变：J4125 是 4 核低频，按 3 倍保守估，720p 整帧约 200ms、
采集 2fps（500ms 一拍）时约占四成 —— **还能跑，但没有余量**。
上机前应在目标机上实测一次，而不是信这个数字。

## 10.5 真光柱：不是游戏没有，是阈值按模拟器调的（同日修）

用户一句话戳穿了 10.1 里那行"光柱关闭"：**"有真光柱的"**。查下去发现三层错，
一层比一层难为情：

1. **阈值来源错了。** `sim/scene.py` 画的光柱是 `(36,190,255)` BGR（S=218/V=255）的
   实心亮条；`config.py` 的默认 `hsv.gold` 就定成 `S≥120/V≥180` —— 正好框住模拟器。
   真游戏里光柱是**暗背景上半透明的淡金 + 白热芯**（实测 S≈70~120、V≈120~170），
   连候选都进不去。
2. **然后拿"检不出"当成了"游戏没有"。** 一段 366s 录像 0 检出 → 写进配置：
   "火炬之光 PC 端掉落不走光柱，开着只会误报，直接关掉"，还把功能关了。同一份仓库里
   另一段 162s 录像检出 140/326 tick（多为粉色技能光效误报），这两条数据本来互相矛盾，
   没人对照。
3. **检测链路本身看不见细柱。** 只按饱和度取"金边"时，白芯（S 很低）会被挖掉，
   一根 4px 宽的真光柱裂成左右各 1px 的两条碎边 → 被 `min_width=2` 和高宽比筛掉。
   实测只有 **≥8px 粗**的柱子能过，而真游戏的光柱就是 3~6px。

修法（`vision/detector.py::_detect_pillars`）：

| 改动 | 为什么 |
|---|---|
| 金边 ∪ 白芯 先合成，再找轮廓 | 白芯不再把柱子劈开，3px 宽也能成为一个完整候选 |
| 候选里同时校验"有白芯"和"有彩色边"（`white_core_color_min_ratio`） | 合成后必须补回抗误报：纯白特效无彩边、纯金 UI 无白芯，两头都拒 |
| 新增 `pillar_min_height=45` | 真实帧实测误报是 19px / 44px 的黄色碎片，不是柱 |
| `pillar_max_aspect` 15 → 40 | 3~6px 宽、120px 高 = 高宽比 20~40，卡 15 等于只认模拟器 |
| `hsv.gold` → `[15,70,120]~[40,255,255]` | 按真实帧实测值，不再照抄模拟器 |

验证（都在真实帧上，不是合成）：

```
合成细柱 3px/4px/6px/8px/14px 宽 → 全部检出（修之前只认 14px）
真图 real_darkmap_farm.png      → 检出 2 根，肉眼复核都是竖直金柱（48x172 / 26x97）
7 张无光柱真实帧                → 0 误报
366s 无光柱录像（116 tick 抽样） → 0 误报
162s 有光柱录像                 → 4/326 tick（原来 51/326，多是粉色技能光效误报）
纯白竖条 / 纯金无白芯 / 19px 碎片 → 全部拒绝（新增 3 条用例钉住）
```

`assets/ref/labels.json` 里加了一条 strict 标答：这张真图必须检出 2 根。
**这是第一张"PC 端真游戏、真光柱"的标答**，以前 8 条全是手机端录屏和暗黑4。

**还没解决的**：这张唯一有光柱的样本来自 B 站压缩视频，且画面中央有大量特效把柱子
糊住了，所以召回只能说"至少能看见能确认的那两根"。要把它变成"稳定能捡"，需要
1~2 张你自己的游戏截图（干净暗底 + 一根光柱），我按 `calibrate_hsv.py` 量一次就能定死。

## 10.6 键位：技能栏那个 `A` 是鼠标右键（用户确认，2026-11-23）

我上一节末尾提了个"更致命的问题"：真实截图底部技能栏是 `Q W E R A`，而
`config.yaml` 是 `pickup_key: a`，怀疑"每次拾取其实在放技能"。**这个怀疑是错的**，
用户明确：① 技能栏第 5 格的 `A` 是**鼠标右键**的图例；② 物品拾取的 `A` 就是**键盘 A**。

所以 `decision.pickup_key: a` 原本就是对的，不动。这轮做的是把这条事实钉住，
免得下一个人（或下一个我）再"顺手修"一次：

| 落点 | 内容 |
|---|---|
| `config.yaml` `decision.pickup_key` | 注释写清"键盘 A，技能栏那个 A 是右键，别改" |
| `lessons/tli.md` → `knowledge/game.md` | 键位表加 `技能: Q / W / E / R / 鼠标右键`；禁忌加一条"别把第 5 格 A 当键盘 A" |
| `autogame/sim/scene.py` | 模拟器第 5 格标签从 `A` 改成 `RMB` —— 混淆就是从"看模拟器截图"开始的 |
| `autogame/teach.py` | `_KEY_ACTIONS` 加 `skill`（路径**故意留空**）→ 每次 `teach --check` 都会报"技能没有配置项" |
| `tests/test_teach.py` | `拾取: A` 必须核成 ok（不许报冲突），`技能: …` 必须核成 gap |

## 10.7 顺手暴露的两件事

**① 右键这条路以前一次都没被走过。** 三套执行器里 `button` 字段全链路是通的
（hidg `0x02`、RP2040 固件 `0x02`、舵机 `mouse_right` ch9），但唯一的调用方是左键。
技能槽第 5 格既然就是右键，"第一次放技能"就会第一次走这条路 —— 通道名写错、
`button` 字段被帧最小化丢掉这类错，测试里完全看不出来，真机上表现为"一按就崩"或
"按了没反应但日志全绿"。现已补三条报文级用例锁住（hidg 按下=`0x02` 抬起=`0x00`、
RP2040 转发 `button:"right"`、舵机打 ch9）。

**② `mash.keys` 里有 q/e/r，但没有任何发技能的调用方。** 这是真缺口，不是键位错。
`teach --check` 现在会把它报出来（`[补料] 技能`）。要补的技能循环还缺两件事：
蓝量判据（真实截图里魔力只剩 `10/490`，空蓝硬按等于白按）和 CD 判断。

## 10.8 完整键位（用户确认，2026-11-23）：`QWER` + 右键、`A` 拾取、`D` 交互

```
技能  Q / W / E / R / 鼠标右键        ← 第 5 格界面标 A，实为右键
拾取  键盘 A                          ← decision.pickup_key
交互  键盘 D                          ← decision.interact_key（新增）
走位  点地面（推荐）
返回  ESC
```

`D` 的用途比想象中宽：进 Boss 房、开宝箱、触发任务地点、**打开关卡面板**、选传送门。
这带出两个必须处理的冲突，都已经在代码里落闸：

| 风险 | 处理 |
|---|---|
| `D` 与 WASD **右移同键**（`explore_dirs` / `recovery.KEY_DIRS` 里的 `d`） | `_emit_move_keys` 把 `interact_key` 与 `pickup_key` 一起拦下并记 `blind_tap_violations`；键盘模式下"向右探索"自动退化成点地面 |
| 连按 `D` = 连开面板 / 连走传送门 | `set_burst_forbid([pickup, interact, escape])`，配置白名单里也没有 `d` |
| 脱困时按到 `D` | `RecoveryLadder(forbidden_keys={pickup, interact})` |

为什么这条比拾取键更值得紧张：按 `A` 按错了顶多捡空气；按 `D` 按错了**人物已经
不在那张图上了**，而 journal 里只记了一次普通按键 —— 事后无法从日志复原"为什么
画面变了"。这也是 `interact_key` 不进 `mash.keys` 的原因。

**还是 ❌ 的部分**：D 目前**没有任何调用方**。要把它用起来，缺的不是键位而是三样判据：
① 宝箱/传送门/D 提示的模板或形状特征（现在没有样本）；
② 按下 D 之后"画面该变成什么"的标答（否则分不清"开出面板"和"没反应"）；
③ 关卡面板里的节点识别（`templates/ui/` 仍是空的）。
在拿到这三样之前，任何"自动开箱/进 Boss 房"都只能靠盲按，而盲按 D 会直接换图。

## 10.9 `D` 带出的两处真 bug（都不是"键位填错"那种）

**① 导航在点地模式下也在按 WASD。** `_steer_with_minimap` 无条件走
`_emit_move_keys(keys)`，而目标游戏用点地面移动 —— 也就是说小地图导航每隔 1 秒
会真的按一下 `w` 或 `s`。这游戏 WASD 不是移动键，轻则无反应，重则撞上别的热键；
`a`/`d` 更糟（拾取/交互）。现在 `approach_mode=mouse_click` 时导航**只点地面**，
一个方向键都不发（`test_nav_never_presses_wasd_in_click_mode`）。

**② 方向表里 `d` = 右移，而 `d` = 交互。** 探索/走位/导航三处都会因此"向右走变成
开面板"。处理分两层：

| 层 | 做法 |
|---|---|
| 主动 | `_pressable()` 从方向键里剔掉功能键；剔空就点地面。**不能只拦不补** —— 否则探索少掉 1/4 方向，表现为"右边的东西永远不捡" |
| 兜底 | `_emit_move_keys` 仍然拦截并记 `blind_tap_violations`（恒为 0 才有意义） |

顺带修了测试台：`test_nav_closed_loop` 以前只把 `key_tap` 回放进模拟世界，退化后
发出的点击被丢掉，于是"导航永远到不了"（其实人已经走到了）。回放要覆盖**所有**
移动命令，不然测的是一个不存在的执行路径。

## 11. 换游戏支持度：键位从"写死两档"改成"可教的操作方案"（2026-11-23）

用户提的问题：**「不同的游戏操作方式都不一样，需要有个学习方案，不能一棒子打死」**。
举了两个真实例子——火炬之光靠鼠标左键移动、右键主攻、QWER 辅助；魔兽世界靠 WASD
走位、技能在 1-9 / F1-F9、而且"每个人设置的都不一样"。

### 11.1 原来的支持度：只支持"一类游戏"，不是"支持换游戏"

| | 火炬之光（点地面 ARPG） | 魔兽世界（WASD MMO） | 原来的处理 |
|---|---|---|---|
| 走位 | 左键点地面 | WASD + 鼠标视角 | `approach_mode` 两档，能切 |
| 主攻 | 鼠标右键 | 1 或右键 | **没有这个概念**（只有 mash 白名单） |
| 技能 | QWER | 1-9 / F1-F9 | `mash.keys` 一张白名单，**无调用方** |
| 拾取 | 键盘 A | 无（自动/右键尸体） | `pickup_key` 写死，**没有"没有"这个选项** |
| 交互 | D | 右键点目标 | `interact_key`，**只有键盘键** |

结论：字段能塞进去，语义塞不进去。所以不是"支持度 60%"，而是**"支持换标定、
不支持换操作方式"**。这一节修的就是这件事。

### 11.2 做法：方案管"怎么按"，铁律管"什么时候按"

```
方案（可教、per-profile）        铁律（不可学、不可配）
  move.kind = click | wasd | stick   拾取三道闸 / A框确认帧数
  primary / skills / bindings        fail_closed / 坐标归一化 / 模式闸门
  ↓ 只决定"发哪个物理输入"          ↓ 决定"这一刻允不允许按"
```

方案里**没有 `when` 字段**，这是刻意的：可教的东西一旦包括铁律，"学"就会把铁律学松。
`blind_tap_violations` 抓的是"没证据就按"，不是"按错了键"，两者不能混。

### 11.3 四个"不许假装"的判定

| 状态 | 判据 | 程序行为 |
|---|---|---|
| `ready` | 有绑定 | 该按就按（仍过闸门） |
| `unknown` | 没教过 | **不按**（少捡一件，好过捡一晚上空气） |
| `partial` | 学了但做不准 | 有限使用（WASD 无视角 → 方向不准） |
| `unsupported` | 引擎没原语 | 不做（虚拟摇杆需要"按住拖动"） |

魔兽世界实测：7 项里 5 项就绪，走位 `partial`（不会转视角）、拾取 `unknown`
（不猜一个键去按）。这是"不一棒子打死"的正确形态 —— 能跑一半，剩下的一半
明确写着"为什么跑不了"。

### 11.4 冲突：分界看 `move.kind`，不看字母

`WASD 走位 + 拾取 A` 是致死冲突（A 同时是左移），必须拒绝加载。
但火炬的 A/D 字母和 WASD 一样，它走点地面 → `move.move_keys` 为空 → **不报**。

按"字母相同"判冲突会把一款能跑的游戏拦在门外；按"会不会真的按下这个键"判才对。
`tests/test_input_scheme.py::test_tli_keys_do_not_look_like_conflicts` 钉住这条。

### 11.5 顺带修掉的三个"假生效"

1. **页面改键位不派生** → FSM 读旧的 `pickup_key`。现在 `apply_patch` 含 `input`
   就地重新派生，并把变化写进 `changed`（所以 `LIVE_FIELDS` 加 `input.`）。
2. **直接改派生字段** → 下次加载被覆盖回去（"改了能用一次，重启又变回"）。
   现在直接拒，并告诉人改 `input.bindings`。
3. **方向键映射顺序** → 必须"先映射再拦功能键"。反了会漏：前进键被改成 `a`（拾取键）时
   放行 `w`，实际发出的 `a` 就是一次盲捡。

### 11.6 仍然不支持的（如实记着）

| 缺口 | 影响 | 补法 |
|---|---|---|
| WASD + 鼠标视角 | 魔兽类游戏走不准 | 加视角控制（`mouse_look` 目前只标 `partial`） |
| 虚拟摇杆 | 手游类走不了 | 后端加"按住拖动"原语 |
| 技能循环 | 键位有了，**没有调用方** | 需要蓝量/CD 判据 + 决策层的循环逻辑 |
| 交互（D/右键） | 键位有了，"何时按"没有证据 | 宝箱/传送门/D 提示的模板与标答 |

## 12. 从"支持几款游戏"到"能被教会玩"（2026-11-23）

用户在操作方案之后又提了一层要求：**「将程序做成一个游戏者，不同的游戏需要补充内容和知识去
理解和学习怎么做，而不是直接兼容各个游戏」**。这句话否掉的是"每款游戏一个适配器"的路线。

### 12.1 之前缺的那一层

操作方案（第 11 节）解决"按哪个键"，但"什么时候按、按完算不算成"仍然写在 `fsm.py` 里：
刷图循环是 2000 行 if/else 里的固定路径。表现是：

| 想做 | 之前 | 现在 |
|---|---|---|
| 换一款游戏的目标顺序 | 改代码 | 改 `goals.yaml` |
| 加一个"开箱"步骤 | 改代码 | 改 `skills.yaml` |
| 知道"按了没反应" | 看录像猜 | 效果账本自动累计 |
| 判断"这个游戏现在能玩到什么" | 跑一晚上看日志 | `--check` 一行一行列 |

### 12.2 分层：知识可教，铁律不可教

```
goals（目标）     YAML   ─┐
skills（技能）    YAML   ─┤ 可教：错了顶多效率低
verbs（动作）     代码   ─┤ 证据写死：pickup = 场景门 + 目标 + A 框
effects（效果）   代码   ─┘ 只累计证据，只出假设
```

关键决定：**证据是动词自带的，技能文件关不掉**。技能是知识，可以错、可以被改；
而"没看到 A 框不许按拾取键"一旦也能被知识覆盖，"学"就会把铁律学松。

### 12.3 三个"不假装"的计数器

`blocked_capability`（没教就不做，立即换技能）、`blocked_evidence`（没证据不按）、
`noop_completion`（0 动作就"完成" → 判据写错，三次后封掉）。这三个数是"假运行"的三个来源，
以前都只表现为"日志全绿、游戏里什么都没发生"。

### 12.4 效果账本：两种口径，不能混

走位看**画面有没有动**（相机跟随时角色恒在屏幕中心，位置签名不变）；
拾取/攻击看**语义状态有没有变**（东西少了一个、怪变少、界面切走了）。
混用会出两种错：走位永远"没效果"（假故障），或者飘个特效就被当成"捡到了"（假成功）。

### 12.5 写知识时踩到的坑（都变成 lint 错误了）

1. 拾取的 `until` 写 `not_aframe` → 人还没走到就判定做完（首次实现就踩了，跑出来"技能飞快、
   什么都没捡"）。
2. `target_gone` 用屏幕坐标判断 → 相机一跟，目标在屏幕上跑，被误判成"消失"。
   改成**按数量**：动之前记下几根光柱，现在少了就是捡到了。
3. `move_to` 在"没目标"时不能退化成点屏幕中心 —— 所以探索单独做成 `roam` 动词，
   而不是给 `move_to` 开后门。
4. 鼠标主攻没有目标时不能点当前光标（等于朝上次停的地方挥一刀，日志看不出异常）。

### 12.6 仍然缺的（判据，不是结构）

技能循环（QWER 有键位，没有蓝量/CD 判据）、开箱/进门的"何时按"（缺 D 提示的视觉证据）、
换图/选关（缺面板节点识别）。这三项有了截图标答就能写成 YAML，不用改代码。


## 13. 判据层：把"什么时候按"也从代码里拿出来（2026-11-23）

第 12 节结尾写了：技能循环、开箱、换图缺的是判据，不是结构。这一节补上那块结构。

### 13.1 决定

判据（蓝量够不够、提示在不在）**不进 `SceneState`**。血条位置、图标样式每款游戏都不一样，
塞进协议等于把协议长成某一款游戏的形状。单开 `autogame/agent/cues.py`：
`profiles/<id>/agent/cues.yaml` 写 id/region/color/阈值，技能步骤用 `when: cue` + `cue: <id>` 引用。

三种读法：`ratio`（区域里像这个颜色的像素占比）、`bright`（平均亮度）、
`template`（模板匹配分，模板图放 `agent/` 目录）。region 归一化，换分辨率不用重标。

### 13.2 阈值不手填

`tools/learn_cue.py` 对着"成立 / 不成立"两张截图取中间值写进 YAML。
手填的数字两周后没人验证得动；中间值是唯一能自证的数字 —— 判错了回头看，
知道当时按哪两张图定的。模板类直接从截图 `--crop` 裁一块存成文件。

### 13.3 倒的方向是设计出来的

读不出来一律当**不成立**，不是沿用上一帧：没有画面 → 全 0；区域越界 / 模板缺文件 → 0 并记
`last_errors`；没写阈值 → lint error（不是"永远成立"）。理由和拾取三道闸同源：
**缺证据只能让动作变少**。反过来就是"画面一片黑也照按"。

顺带一条假设通道：某判据几百帧一次没成立，`hypotheses()` 报"区域可能标错了，也可能这局确实
没有"—— 两种可能都写上，人判，程序不改配置。

### 13.4 顺手做对的两件事

- **`repeat` 有上限是刻意的**。无上限循环在"技能永远不生效"时会按一整晚，那正是最该停的时候。
  `until` 在轮边界判而不是每帧判 —— 否则"打完捡掉落"的收尾会被"怪没了"当场砍掉。
- **模拟器补了 HP/MP 条**（`SimWorld.vitals_region()`）。判据层要能陪练：技能按键真的扣蓝、
  蓝条真的会画短，`tools/agent_play.py` 里判据读的是真读数，不是摆设。

### 13.5 接入点（都是既有的口，没有新开洞）

preflight `_check_agent` 与页面 `agent_report` 走 `kn.summary()/report()`（已含判据条数与
`last_errors`）；`GamePlayer.on_scene` 多收一个 `frame` 参数，判据在决策线程里算，**不在
WS 读线程**；tli 的 `cues.yaml` 故意留空 —— 没有实拍图就填假数字，和"蓝真的一直不够"在
日志里一模一样。

测试：`tests/test_cues.py`（读数/倒向/标定/lint/帧缺失），`pytest` 全量绿。
