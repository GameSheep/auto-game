# 8. 自主性升级（2026-11-16 第三轮）

用户要求："提高 LLM 和视觉模型调用，作为搬砖机器人要有更高智能，绝对不能卡壳。"
这一轮不加新功能面，只补**长期无人值守**这一维（原来只有单目标级别的"放弃+拉黑"）。

## 8.1 之前缺的是什么

原来的"不卡死"只覆盖单目标：走位 8s 超时 → 放弃拉黑 → 继续扫描。但真实搬砖会卡在
**规则覆盖不到的地方**，而且每种都会让机器人"安静地站着"：

| 卡法 | 原来的表现 |
|---|---|
| 撞在墙角/被地形挡住 | 目标拉黑后换个目标，仍在原地撞 |
| 房间走完但没有掉落 | 站着等刷新（explore 默认关） |
| 弹窗/菜单/结算界面没退出 | 场景门拦截 → **零命令**，永久静止 |
| 游戏假死/窗口失焦 | 画面不动，无任何判据 |
| 代理掉线 | 服务端无帧，但仪表盘仍显示"运行中" |
| 代理重启导致帧时间戳回退 | 所有超时判据算出负数 → 逻辑错乱 |

## 8.2 现在的结构（三层）

1. **看门狗**（`decision/recovery.py::ProgressMonitor`）：frozen / idle / stalled / gated / loading
   五态判定，全部基于帧时间戳；`frozen` 还要求"我们确实发过动作却没反应"，
   避免把"站着没事干"误判成卡死。
2. **恢复阶梯**（`RecoveryLadder`）：重定位 → 四向探路 → ESC → 脱困键 → 重新聚焦 →
   八向脱困 → 重开关卡 → VLM → LLM → 新一轮（降速 + 告警，`max_cycles=0` 无限重试）。
3. **模型顾问**：VLM 看截图给动作（白名单 + 坐标钳制 + 每分钟预算 + 熔断 + 后台线程），
   LLM 看摘要给策略（explore/reset_stage/wait/panic）。两者都只是"顾问"，不能按拾取键。

另外补了程序自身的健壮性：帧流看门狗（10s 无帧告警、恢复后消警，**无画面绝不盲动**）、
时间戳回退重基准、`/api/autonomy` 排障接口、仪表盘「自主恢复」面板。

## 8.3 一个真实的设计 bug（这轮发现并修掉）

`pickup_key: a` 与 WASD 左移同键。原来的 `explore` 直接按方向键，**一探索就等于盲捡**。
端到端测试立刻抓到：模拟世界 `blind_a_press` 从 0 变成 17。
修法两层：
- 探索/脱困改为**点地面**（mouse_click 模式），从根上不碰键盘；
- `_emit_move_keys` 闸门：任何走位按键只要等于拾取键就拦截并计入 `blind_tap_violations`。
现在三种卡壳场景 + 全量 199 用例里，盲按恒为 0。

## 9.2 这一轮发现并修掉的真实 bug

1. **"取消"会把补丁打上。** 确认框的选项就是 `["确认","取消"]`，先比选项文本时
   "取消"命中第 2 个选项 → 被当成"选了取消" → 拿着 payload 去 apply。
   人越想取消，改动越会被打上。改成"确认/取消/编号"先于选项文本。
2. **观察模式把引擎停掉了。** `_hard_stop` 对 observe 也调 `fsm.stop()`，
   于是"观察"实际上什么都不观察。拆成 `_release(stop_engine=...)`。
3. **暂停到点不会自己接着跑。** 模式恢复到 COOP/FPS 状态还是 PAUSED，没人点亮引擎。
   模式管理器加 `on_change` 回调（锁外通知），到点自动 `_engine_start()`。
4. **页面按钮绕过模式。** `hub.control("start")` 只动 FSM，模式还停在暂停，
   表现是"显示在跑、动作全被拦"的假运行。改成两者一起动。
5. **改完规则没重载。** 补丁写完文件，`Arbiter` 还是启动时那套 —— 下次重启才生效。
   现在写完当场 `reload_rules()`；配置补丁也当场 `apply_patch` 并报告需重启字段。
6. **学习完不生效、还会被旧基线误判。** 换代后规则没重载、体检基线还是旧配方的，
   于是新代上线第一分钟就报"变慢"然后被回滚。加 `evolve.set_generation_hook`。
7. **FSM 事件进不了现场记录。** 只在开了 `event_log` 时才挂回调，关掉审计日志的机器上，
   "急停/卡死/进恢复"这些最该被解释的事全都看不到。
8. **过期提问被当成"没有在等确认的事"。** 用户明明看着问题框回答，得到的却是
   "现在没有在等确认的事"。过期现在会明确说"过去太久了，重新问"。
9. **规则补丁"覆盖"是空操作。** `PatchStore._build_rule` 里 `rules = [...]`
   只重绑了局部变量，`doc["rules"]` 还指着原列表 —— 补丁账本记成已应用、校验还说
   "原有规则都在"，文件一个字没变。经验晋升靠这条路径改门槛，表现就是"学了但没变"。
   现在写回 `doc["rules"]`，并有用例钉住（`test_rule_patch_overwrites_an_existing_rule_for_real`）。
10. **stall 规则限流用 `0.0` 当"从没拦过"。** 帧时间从 0 开始，于是开跑前 10 秒
    规则被白白抑制。改成 `None` 哨兵。
11. **RP2040 的鼠标坐标从来没换算过（真机上鼠标等于全废）。** 固件的鼠标描述符
    声明的是绝对坐标、Logical Max 32767，它对收到的数字不做任何换算；而主机的
    `RP2040Executor` 把**像素坐标直接发过去**。1280×720 画面里点 (640,360)，
    固件收到 640，光标落在屏幕 2% 处。hidg 后端早就用 `build_abs_mouse_report`
    做了归一化，RP2040 这条路径漏了 —— 而两边日志都显示"下发成功"。
    现有用例 `test_rp2040_json_framing` 当初是按"像素直发"写的，等于把这个错误
    固化成了规格。现在换算统一放在 `_write`（唯一出口），并有用例钉住
    "同一像素坐标在两个后端落到同一位置"。
12. **`runtime_overlay_path("")` 直接抛 `ValueError`。** `Path("")` 是 `Path(".")`，
    对它调 `with_name` 会炸。这条路径会在"经验想把配置写进 overlay"时被走到，
    表现是"配置补丁写不进去"，原因却是一句 `WindowsPath('.') has an empty name`。
    现在退到数据根下的 `config.yaml`，既不抛异常，也不会在 cwd 里凭空多出一份
    永远读不到的覆盖文件。

## 9.4 经验长成规则：从"记下来"到"会用了"

上一轮的经验闭环只写到手册：候选晋升后多一条给人看的文字，程序的行为一点没变。
这一轮把它接到规则上 —— 学到的经验下一次**当场**改变动作。

| 连接处 | 之前 | 现在 |
|---|---|---|
| 规则语言的事实 | 只有画面类（pillars/monsters/…） | 加 `repeat` / `repeat_key` / `recoveries` / `picks_delta` / `no_progress_for` / `intent_churn` / `cmds`，全部来自 probe 每 tick 真的产出的字段 |
| probe 产出 | 没有 `repeat`，也没有"最近一分钟进恢复几次" | `_arb_probe` 用 `monitor.recent_repeat`（与体检同一份实现）+ `_recovery_ts` 现算 |
| 求值时机 | 只有 `idle`（FSM 停手 ≥1.5s） | 加 `trigger: stall`：卡住那会儿 FSM 一点都不闲，等停手等于永不生效 |
| 救场限流 | 硬编码 10 秒常量 | `arbiter.rule_stall_gap_s` 可调：不同游戏"卡住"能持续的时间差一个量级 |
| 晋升 | 只写 `lesson` | 写 `lesson` + `rule`，规则走 `PatchStore`（预览/校验/原件/可回滚），写完 `reload_rules()` |
| 页面 | 只有"记进手册"按钮 | 候选上直接显示"会写成规则：当 … → …"，写不出的显示原因 |

四条硬规矩（都是为了"不许假装学会"）：

1. **条件只准引用真会产出的事实。** 引用缺席字段的规则能过校验、能写进 rules.yaml，
   然后一次都不命中 —— 页面上却显示"已经学会"。
2. **缺字段必须求值成 unknown。** 监督层关掉时 `picks_delta` 这一组**不出现**，不填 0；
   填 0 会让 `picks_delta == 0` 在"根本没在测"的时候命中，规则去治错病。
3. **门槛比告警线更早。** 体检在重复 12 次时告警，规则取 `0.75N`（约 9 次）介入。
4. **写不出规则的，改配置，不硬编动作。** `slow` / `model_burn` 这一类治的是"负担"，
   而动作清单里只有 9 个游戏内行为（走开/打/捡/等/导航/重挑/重置/ESC），没有
   "降级""少问模型"这类动作 —— 硬写规则只会在慢的时候让角色随便走两步。
   它们改成生成**配置补丁**：`slow` → `decision.tick_hz = 0.5`，
   `model_burn` → `decision.arbiter.cooldown_s = 60`，走 `PatchStore` 的 config 路径
   （写 `config.runtime.yaml`，删掉即回滚），晋升后当场 `apply_patch` 到内存。
   候选上 `kind` 会写 `lesson+config`，页面显示"会改配置：decision.tick_hz = 0.5"。

## 9.5 上真机前自检：把"静默失效"变成"上机前就看见"

`doctor.py` 回答的是"这台机器能不能**起来**"（升级闸门）；真机上真正难查的是
**"起来了但动作全废"**，两条路完全不同，所以新加了 `preflight.py`。

| 检查 | 真机上的意义 | 不过时 |
|---|---|---|
| 执行器探活 | `ping` 回 `{"ok":true,"fw":"1.1.0"}` 才算对面真是这块固件 | fail |
| 固件版本 | 回 `unknown op` = 是这套固件但太旧，**要重刷**（与"对面不是这板子"是两种修法） | fail |
| 能松手 | 发一次 `stop_all`（只松不按，最安全的探针） | fail |
| 动作闸门 | 模式/闸门任一关着，上机也一步不走 | fail |
| 采集在流 | 最近一帧超过 3 秒 = 瞎子 | fail |
| 画面尺寸 | 帧 1280×720 vs `screen_w` 1920×1080 → 点中心落到 (960,540) | fail |
| 采集区域偏移 | `capture.region` 的 left/top ≠ 0，而下发坐标没加偏移 | fail |
| 角色位置 | 坐标出画面 = 标定参考分辨率不对 | fail（缺角色只 warn） |
| 采集/决策频率 | 决策 2Hz 高于采集 0.5fps = 同一个画面被决策多次 | warn |

三条设计上的取舍：

- **结论是三档**（`ok` / `dry` / `blocked`）。`dry` 是刻意保留的中间态：
  用 dryrun 在真机环境跑通链路完全合理，算成失败会逼人说谎；但它绝不能显示成
  `ok`，那正是"以为在跑"的来源。探活被跳过时文案是"没验证硬件"，与
  "确定不会动手"分开说。
- **服务在跑时不做串口探活。** 插一句 `ping` 会抢走正在下发命令的回显，
  既可能把好固件误判成故障，也会打乱那条命令的 ack。此时报 `skip`，提示先暂停。
- **`probe()` 默认实现返回失败而不是 True。** 新加的后端忘了实现探活，
  自检会拦下来说"这个后端没有探活"，不会默默放行。

`tools/e2e_real_screen.py` 也跟着改了：`--backend` 可选真后端（默认仍 dryrun），
抓帧后立刻比对帧尺寸与 `screen_w/h`，不一致就拒绝开始（`--yes` 可强过）；
真后端会先提醒"确认游戏窗口在前台"；跑完再输出一段上机自检结论。


## 9.6 放行度：把"限制太多"从感觉变成一张表

用户上真机前的原话是"限制太多了"。这句话背后是一个具体问题：限制不是不存在，
而是散在 **38 个配置字段**里 —— 采集 2fps、轨迹 0.45s、疲劳满了休息 20-90s、
走位超时 8s、裁决冷却 20s……打开 `config.yaml` 只能看到一串数字，不知道哪个是瓶颈，
改完也不知道有没有用。**没有对账的"可调"等于没调。**

| | 之前 | 现在 |
|---|---|---|
| 想快一点 | 凭手感改 `config.yaml`，改完不知道哪条起了作用 | 页面三档一键切（保守 / 平衡 / 搬砖），只动节奏类字段 |
| 不知道瓶颈 | 只能读源码猜 | 表里每条都写"它在防什么" + 当前值 + 最松值 |
| 被拦了没证据 | 只知道"好像没动" | 对账把 `dropped` / `suppressed` / `targets_ignored` / `walk_no_progress` / `human_breaks` 翻译成"被拦了多少、为什么" |
| 松了怕出事 | 无差别手改，可能顺手放松了铁律 | 铁律单列只读，**档位 patch 里根本不包含它们**，有测试断言 |

实测（同种子、同 60 秒、同一条链路）：

```
档位                拾取     /分钟     动作    空按     丢/拦    盲按
保守（默认）             5     5.0     27     0     0/0     0
平衡                 7     7.0     41     0     0/0     0
搬砖（最松）            11    11.0     53     0     0/0     0
```

搬砖档产出 ×2.20、动作 ×1.96、空按 0、盲按 0 —— 变快没有靠放松任何一条铁律。
复现：`py -3.12 tools/limits_bench.py --seconds 60`。

**顺带修掉一个真 bug（假生效）**：`capture.fps` 之前只在代理 `hello` 时下发一次，
页面改 fps 之后服务端配置变了、代理还按老帧率采图 —— 表现为"调了没用"，
比调不了更糟（用户会因此把有效的开关关掉）。现在切档和 `/api/capture` 都会
把新参数推给已连接的代理，返回里带 `pushed` 说明推没推到。

## 9.7 仍然缺的（诚实说明）

1. **真机 + 真游戏**：现在有了 `preflight` 和 `e2e_real_screen --backend`，
   能在上机前把"静默失效"拦掉；但"对着真实游戏窗口连续跑 30 分钟、看它能不能
   真的刷完一圈"这一关，仍然必须在有硬件和游戏的地方过。代码侧能做的已经做完：
   坐标换算、探活、尺寸一致性、松手检查都有用例。
2. **sherpa 模型未装**：语音服务端识别/合成只用假模块验证了调用形状，
   真模型的中文识别率没有数据；默认路径是浏览器识别，不受影响。
3. **经验规则的覆盖面**：`repeat` / `recovery_spin` 生成规则，`slow` / `model_burn`
   生成配置补丁。仍有一类结论没有归宿 —— 体检报"没进展"但既不是卡住也不是空转时，
   现在的模板里没有对应项，只会被 `_judge` 记成日志。要补得先确定它该改动作还是改参数。
4. **代码补丁（对话第三阶段）**：不做，改代码走 `upgrade` 整包换代。
   配置里也刻意没有 `allow_code` 开关 —— 一个设了也不生效的开关比没有更误导。
