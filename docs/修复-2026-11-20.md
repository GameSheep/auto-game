# 2026-11-20 真实录像暴露的四个问题与修复

素材：`屏幕录制 2026-11-20 193338.mp4`（2560×1380 / 30fps / 334.3 秒 / 601MB，
火炬之光无限 PC 端完整一轮刷图）。回放方式 `tools/video_batch.py --hz 2`，
逐帧产物 `assets/frames_replay/real_20261120_1933/`，审查页
`assets/frames_replay/report.html`。

---

## ① 怪物检测在这款游戏上 100% 误报

**症状**：669 帧里 564 个"怪物"检出，按坐标裁 16 格拼图，**0 格是真怪**
（红岩、冰面、火焰特效、技能图标、玩家自己）。触发 51 次"攻击怪物"。

**根因**：判据是「高饱和色块 + 面积/填充率 + 时域确认」，而时域确认用
**屏幕绝对坐标位移 ≥ 2px** 判"这东西在动"。ARPG 镜头跟随角色，角色一走
整片背景都在平移，静止的岩石于是"看起来在动"，顺利通过确认。

**修法**：加**血条闸门**（`vision.monster_hpbar`，默认开）。
候选框正上方 0.02~0.85 倍候选高度内，必须有一条横向居中的细长条：

- 颜色：红（H 0-10 / 170-179）、绿青（H 38-95）、橙黄（H 12-35）
- 尺寸：宽 14~220、高 2~14、宽高比 ≥ 2.2、填充率 ≥ 0.45
- **宽度必须是候选框宽度的 0.3~1.6 倍**（地形管道的亮边横跨半个屏幕，配不上）
- 饱和度和亮度下限 150/130（地形暗红边缘 V 明显更低）

地形、火焰、技能图标没有"头顶 3~8px 的纯色条"，这一条就够把它们挡掉。

**效果**：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 放行帧上的怪物检出 | 197 | **2** |
| 抽样 16 格里的真怪 | 0 | **2/2（100%）** |
| "攻击怪物"命令 | 51 | **2** |

代价是召回率下降（同一段里肉眼可见 6 个怪，只认出 2 个）——精度优先：
误点地形只是白走一步，误点 UI 可能换装/洗点。

## ② 66% 的指令是 4 个固定点循环

**症状**：232 条命令里 154 条是 `(640,125)×40 / (860,345)×40 / (640,565)×38 /
(420,345)×36`。四个点，机械得像脚本。

**根因有两层**：

1. **坐标基准混用（真 bug）**：`detector.py` 里 `char_x, char_y = ww // 2, wh // 2`
   用的是**缩放后**尺寸，而 `SceneState.w/h` 是**原始**尺寸。2560 宽的帧被缩到
   1280 检测，于是 `character=(640,345)` 落在 2560 宽画面的**左 1/4** ——
   所有走位点整体偏到左边。`_detect_pillars` 里的 `distance` 同样混用两套基准。
2. **探索落点写死**：`角色中心 + 方向键向量 × 220`，方向只有 4 个、距离恒定。

**修法**：

- 角色位置统一用**原始帧坐标**对外（`character` / 光柱 `distance` / 走位点一致）。
- 角色定位不再写死中心：`vision.character_track`（默认开）用**帧差**在中心区
  找"最静的一块"——镜头跟随角色，角色相对屏幕几乎不动、背景在动。三道保险：
  只在中心区搜（22%~78% / 28%~80%）、偏移限幅 ±12%、指数平滑 +
  "最静块没比中心块安静 2 灰度以上就用中心"（站着不动时整屏都静止）。
- 探索落点改成 **8 扇区轮转 + 角度 ±16° + 距离 14%~26% 画面短边**，
  优先去"去得最少"的扇区，并避开上一次的落点。

**效果**：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 唯一点击点位 | 4 | **246 / 246** |
| 点击 x 范围 | 640~860（左 1/4） | 676~2072（全宽） |
| 角色位置 | 写死 (1280,690) | 972~1584 × 550~852（随画面） |

## ③ 光柱 / A框判据对这款游戏是空转

**症状**：334 秒里光柱帧 1、A框 14 次全是散点误报（坐标各异、尺寸都是默认
30×30），按 A 次数 0。掉落实际走的是"地面文字标签"（227 帧有标签）。

**根因**：`templates/aframe.png` 是暗黑4 裁的方框，火炬之光 PC 端没有这个方框——
它的拾取提示就是地面标签本身（字母 + 物品名）。光柱同理，这款游戏的掉落不走光柱。

**修法**：新增**地面标签近距拾取**（`decision.label_pickup_when_near`，
config.yaml 里对 TLI 开启）。走到标签跟前时按一次拾取键，四个前提全满足才按：

1. 配置显式开启（没有拾取键的游戏不会误开）；
2. 最近标签与角色中心距 ≤ `label_pickup_near_ratio`（0.14 × 画面短边）；
3. 同一位置连续可见 ≥ `label_pickup_min_frames`（2 帧，容差 5% 画面短边）；
4. 同一个标签最多按 2 次，按不动就交给恢复阶梯。

"绝不盲按"这条铁律没有松动：仍然是**先有像素证据（标签在跟前且连续可见）
再按键**，和 A框路径同级，只是证据来源从"方框模板"换成"标签位置"。

光柱判据保留（对暗黑4 类游戏有效），但在 TLI profile 下不会误触发。

**R4 检查的口径同步改了**（这条很容易自欺，所以写清楚）：
`tools/video_batch.py` 原来判"按拾取键时必须有 A框"，新路径一按就报 3 条 R4
违规。直接放宽检查等于把铁律改成"随便按"，所以改成把**证据定义**写进代码：
`_pickup_evidence()` —— A框出现，**或** 最近标签落在 `label_pickup_near_ratio`
之内。两条都不满足才叫盲按。测试 `test_pickup_evidence_accepts_near_ground_label`
守住这个口径（近距算、远处不算、配置没开不算）。

回放结果：**按 A 3 次**，三次都有近距证据（144px / 182px / 158px），
R4 违规 0。

## ④ 恢复阶梯绕过门禁（修 ①②③ 时新发现）

**症状**：修完上面三条后回放出现 **2 条 R3 违规**（"门禁关闭却有命令"）：
`01:38.00 MOUSE_CLICK (1494,580)`、`01:41.50 MOUSE_CLICK (1516,594)` ——
落在**星图界面的关卡节点**上。

**根因**：`_tick_gated` 里 `if self.state == State.RECOVERING: self._tick_recovery(...)`
——恢复中遇到非战斗界面，会继续走恢复阶梯，而阶梯的 L1 就是"探路点击"。
门禁说"这不是战斗"，恢复阶梯却照样点，等于把门禁绕过去了。之前没暴露是因为
恢复阶梯恰好没在这段录像的 UI 界面上触发过。

**修法**：`_tick_recovery` 里加门禁闸门——`scene.in_game=False` 时只允许
`stop_all` 和脱困键（`esc` / `space` / `dodge_key`），点击/移动一律丢弃并计入
`stats["gate_blocked_recovery"]`。ESC 仍然要能发，否则界面卡住就永远出不来。

**效果**：R3 违规 2 → **0**，同时 ESC 自救路径不受影响
（`test_escape_step_works_when_gate_says_not_in_game` 仍绿）。

# 第二轮（2026-11-21）：把上面三条遗留修掉

结论先说：三条遗留都处理了，但过程中挖出一个**更要紧的错**——之前"2 个真怪"
其实是**玩家自己的铭牌血条**在给地形作保。

## ⑤ 玩家铭牌血条在给地形"作保"（新发现，最严重）

**怎么发现的**：放大核对时发现屏幕中心 (644,258) 那条血条在 5 分钟里
**位置和填充比例一模一样**（绿 15% + 橙 45% + 灰空槽）。它不是某个怪的血条，
而是**玩家自己头顶的铭牌**（绿 HP + 蓝 MP 两行）。

**为什么致命**：玩家永远在画面中心，铭牌条因此是全画面**最稳定**的条。
"候选框上方有条 → 是怪"这条判据一旦用它作保，角色周围任何一块岩石、
机械、栏杆都会被判成怪物。上一轮统计里"放行帧 2 个怪物、抽样 2/2 真怪"
就是这两帧的巧合 —— 它们其实是玩家自己。

**修法**：`PLAYER_BAR_BOX` —— 落在角色附近（横向 ±0.14 屏宽、上方 0.30 /
下方 0.10 屏高）的条一律不算怪物证据；同时 `PLAYER_SELF_RADIUS`（0.08 屏高）
把角色自己的色块也排除。

## ⑥ 怪物检测整体改成"血条为锚"

原来顺序是"先找饱和色块，再看头顶有没有条"。这个方向对这款游戏是错的：

* 火炬之光的怪多是**淡色冰霜怪**，饱和度低到进不了色块候选（S<100）；
* 反过来，地形岩石、火焰、金色建筑全是高饱和色块。

于是改成：**血条是游戏自己画的"这是敌人"标记，先找条，再在条正下方找身体**。

| 环节 | 做法 |
|---|---|
| 找条 | 只认**纯红**（H 0-10 / 170-179）。橙黄会把鎏金柱子一起收进来——实测 41 个检出里近一半是建筑 |
| 条的位置 | 必须落在战斗区内（顶部 HUD 带、底部技能栏的条不算） |
| 条的颜色 | 血条只有一段是彩色（剩余血量），其余是灰空槽 → 横向闭运算把碎片接回整条 |
| 找身体 | 条**正下方** `[条底+1, 条底+2.5×条宽]`、横向 `±0.6×条宽`；两档掩码（饱和 + 淡青）覆盖冰霜怪 |
| 去重 | 一只怪有 HP/MP 两条 → 按身体位置去重（否则同一只怪被记两次） |
| 文字排除 | 候选**中心**落在掉落标签里才丢弃（原来是"任意重叠"，把带名字的怪整批误杀） |
| 时域 | 血条锚定的候选**不等第二帧**：2Hz 采样下镜头跟着玩家滚，同一个怪两帧能位移 100+px，等确认就全漏 |

## ⑦ 光柱 / A框：按 profile 关掉

新增 `vision.pillar_enabled`、`vision.aframe.enabled`（默认都 True，老 profile 不受影响），
`config.yaml` 里对火炬之光 PC 端都设为 `false`。

* 光柱：334 秒录像里光柱帧 1 个、全是散点误报，按 A 次数 0 → 关掉省 CPU；
* A框：14 次全是伤害数字/技能图标 → 关掉。拾取提示改用地面标签（`label_pickup_when_near`）。

# 第三轮（2026-11-22）：运动判据是死路，改做"UI 黑框 + 配对几何"

上一轮结尾写的"用 phaseCorrelate 做背景补偿"我去做了，**结论是这条路不通**。
真正把误报压下去的是另外两条物理判据。

## ⑧ 先修一个工具 bug：核对取帧偏了 14 帧

`tools/frame_check.py`（原 `_check_frames.py`）原来每个 tick 都
`grab(step-1)` 再 `read()`。`read()` 自己就消耗一帧，于是 tick k 实际读到
第 `step-1 + step*k` 帧，整段偏 14 帧（step=15）。

后果不是"看错几张图"这么轻：**我用偏掉的帧做的对比实验，结论全是错的**
（"真条黑框比 0.23 通过""k559 只有 1 个怪"这些都是在错的帧上量的）。
`video_batch.py` 用的是 `fi % step == 0`，索引是对的 —— 只有临时脚本错了。

## ⑨ 背景补偿运动判据：实测无效，不做

原计划：用 `phaseCorrelate` 估镜头全局位移，要求候选**相对背景**有位移。

实测（1933 录像，2Hz 采样）：

| 量 | 结果 |
|---|---|
| 相位相关响应 `resp` 中位数 | **0.11**（>0.3 才算可信） |
| 对齐后残差 vs 不对齐残差 | **基本相同** |

原因很朴素：这段录像大部分时间**角色站着不动**，镜头也不动。2Hz 下镜头
偶尔一帧平移 400px，相位相关直接失效；镜头不动时静态景物和站桩怪在运动上
**完全无法区分**。所以"用运动分静态景物"在这份数据上没有信息量。

（顺带量了结构判据：条宽/身体宽、身体顶部宽度占比、血条填充比 —— 三组
分布全部重叠，`r=0.95` 的是地形、`r=0.88` 的是真怪。也放弃。）

## ⑩ 黑框判据：真血条是"UI 控件"，假血条是"柔和色带"

把原分辨率（2560 宽）的真条放大 8 倍才看清：真血条是**锐利的圆角矩形 +
1~2px 纯黑描边 + 纯红填充**；地形红边、技能特效是柔和渐变，外圈亮度和
填充几乎一样。

量化（原分辨率，上下边线平均亮度 / 填充平均亮度）：

| 对象 | ring/fill |
|---|---|
| 真血条（tick559，2144,157） | **0.24** |
| 地形红色亮边（8 处） | 0.75 ~ 0.98 |

阈值取 0.60。**必须在原始帧上验**：1280 下采样会把 2px 黑边糊进红里，
比值失真。粗筛仍在 1280 上跑（快），逐条回原图验黑框。

## ⑪ 配对几何：三条物理约束

条找到了不等于怪找到了，还得在条下方找到**同一个**怪的身体。真实录像里
最常见的误报是"条是真的、下面的身体配到了地形块"。三条约束：

| 约束 | 取值 | 依据 |
|---|---|---|
| 条宽 / 身体宽 | 0.45 ~ 3.2 | 头顶条按怪物宽度画；误报全落在 0.15~0.35 |
| 水平居中 | \|条中心−身体中心\| ≤ 0.6×条宽 | 身体轮廓只覆盖精灵一部分，0.35 倍会差 0.25px 拒掉真怪 |
| 纵向 | 身体必须伸到条下方，且身体顶边不低于条底 −0.9×身体高 | TLI 高个怪（冰晶簇）血条压在身体上部：条底 y=82、身体 y=68~137 |
