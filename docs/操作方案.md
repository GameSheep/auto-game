# 操作方案：让同一套引擎跑不同的游戏

> 「不同的游戏操作方式都不一样，感觉需要有个学习方案，不能一棒子打死。」
> —— 这条需求的结论就是本文档描述的 `input/scheme.py`。

## 1. 问题在哪

原来的键位是**按一款游戏写死**的：

| 字段 | 火炬之光（点地面 ARPG） | 魔兽世界（WASD MMO） |
|---|---|---|
| `decision.approach_mode` | `mouse_click` | `keys` |
| `decision.pickup_key` | `a`（捡东西） | `a` 是**向左走** |
| `decision.interact_key` | `d`（开箱/进房） | `d` 是**向右走** |
| 技能 | `q w e r` | `1-9`、`F1-F9`，每人不同 |
| 主攻 | 鼠标右键 | `1` 或右键 |

字段能塞进去，语义塞不进去。再加两档 `approach_mode` 也只是把
"能配的错"从两种变成四种 —— 因为差异不在"档位数量"，在**每个动作
靠什么触发**，而这是每款游戏都不同的知识。

## 2. 分两层：方案管"怎么按"，铁律管"什么时候按"

```
┌─────────────────────── 方案（可教 / 可换） ───────────────────────┐
│  走位：点地面(左键) | WASD(固定视角) | WASD(鼠标视角) | 摇杆       │
│  主攻：右键按住 / 1 连按                                          │
│  技能：q w e r                                                    │
│  拾取：A     交互：D     返回：ESC     地图：M                     │
└───────────────────────────────┬───────────────────────────────────┘
                                │ 只决定"发哪个物理输入"
┌───────────────────────────────▼───────────────────────────────────┐
│                   铁律（不可学 / 不可配）                          │
│  拾取三道闸：场景门 → A框 → 目标存在                               │
│  fail_closed、确认帧数、坐标归一化、模式闸门                        │
│  blind_tap_violations 必须恒为 0                                   │
└───────────────────────────────────────────────────────────────────┘
```

**方案里没有 `when` 字段，这是故意的。** "A 是捡东西"可以问出来、可以试出来，
错了顶多捡不到；"看到 A 框就按"一旦也能被学，等于允许"学"把铁律学松。

## 3. 模型

```yaml
# profiles/<id>/scheme.yaml
name: 火炬之光：无限（PC 键位）
move:                       # 走路：四种形态
  kind: click               # click | wasd | stick | none
  button: mouse_left        # click/stick 用哪个鼠标键（有的 ARPG 走位是右键）
# kind: wasd 时：
#   camera: mouse_look      # fixed=俯视固定视角；mouse_look=视角跟鼠标（魔兽）
#   keys: {forward: w, back: s, left: a, right: d}
primary:                    # 主攻
  key: mouse_right
  action: hold              # tap=按一下 | hold=按住连发 | mash=连按
skills:
  - {id: 技能1, key: q}
bindings:                   # 一次性动作
  pickup:   {key: a}
  interact: {key: d}
  cancel:   {key: escape}
```

`action` 三档不是风格问题。按住连发的游戏用 `tap` 驱动，表现是
"打得很慢但**没有任何报错**" —— 这类"静默降级"比崩溃难查得多。

## 4. 不知道就说不认识

每项能力有四种状态，页面和 `preflight` 都按它显示：

| 状态 | 含义 | 程序会怎么做 |
|---|---|---|
| `ready` | 配好了 | 该按就按（仍过铁律） |
| `unknown` | 没教过 | **不按**。少捡一件，好过捡一晚上空气 |
| `partial` | 能做但做不准 | 有限使用（如 WASD 无视角控制 → 走位方向不准） |
| `unsupported` | 引擎还不会 | 不做，并说明缺什么原语 |

关键：**没有"猜一个默认值"这一档**。空白方案里 `pickup` 是 `unknown` 而不是
继承 `a` —— 继承会让"换了游戏但忘了配"表现成"程序自己在乱按"。

## 5. 冲突检测：宁可起不来

```python
# 拾取键与移动键重叠 → error，拒绝加载
InputScheme(move=MoveScheme(kind="wasd"), bindings={"pickup": Binding(key="a")})
# InputSchemeError: 操作方案有 1 处致死冲突，拒绝加载：
#   1. 拾取键 A 同时是移动键（走位方案 wasd 的 ['left']）
#      → 改用点地面走位（move.kind=ground_click），或把移动键改成不重叠的布局
```

判定的分界线是 `move.kind`，不是"字母是否相同"：

- 火炬：`a` 是拾取键，WASD 字母里也有 `a`，但走位是点地面 →
  `move.move_keys == set()` → **不报冲突**（误报会把能跑的游戏拦在门外）
- 魔兽：走位是 WASD → `move.move_keys == {w,s,a,d}` → 拾取填 `a` 立刻报错

其他规则：主攻与拾取同键 = `error`（按下去要么放技能要么捡空气，两者都静默失败）；
主攻与交互同键 = `warn`（魔兽本来就是右键既打又交互，由目标决定语义）。

## 6. 怎么教一款新游戏

```bash
# 1) 从预设起步（torchlight PC / wow 已内置）
py -3.12 tools/learn_input.py --profile my_game --preset tli_pc --ask

# 2) 逐项确认：回车保留，- 清空，? 看说明
#    走位 → 主攻 → 拾取 → 交互 → 返回 → 地图 → 技能

# 3) 边按边学（切到游戏里按真实按键，向导抓键名；需要 pynput）
py -3.12 tools/learn_input.py --profile my_game --ask --capture

# 4) 校验，有致死冲突会 exit 1 并且不写文件
py -3.12 tools/learn_input.py --profile my_game --print

# 5) 上机自检里也会有一行"程序实际会按什么"
py -3.12 -m autogame.preflight --profile my_game
```

为什么不做"看录像自动推断"：录像只能看到"某段时间 A 被按了 12 次"，
分不清那是捡东西还是往左走 —— 而这个区别正是铁律守的东西。按键是确定性
知识，问一次比推断一百次便宜。

## 7. 引擎当前的真实短板（不许假装能跑）

| 能力 | 状态 | 缺什么 |
|---|---|---|
| WASD + 鼠标视角走位 | `partial` | 不会转视角。`W` 是"朝面向走"，不先转视角就撞墙 |
| 虚拟摇杆 | `unsupported` | 后端只有 `mouse_click`，没有"按住拖动"原语 |
| 技能循环 | 未实现 | 方案能记下键，但**没有调用方**，也没有蓝量/CD 判据 |
| 交互（D） | 键位已有 | 缺"什么时候该按"的视觉证据（宝箱/传送门/D 提示的模板） |

前两条是方案层的事，后两条是决策层的事。都写在 `capability_table()` 里，
页面上一眼能看到"这款游戏现在能跑到什么程度"，而不是"显示在跑、动作全被拦"。

**不会走位时会关掉走位总闸**（`decision.move_enabled=false`）：探索、导航、追光柱、
侧移脱困、恢复阶梯的探路点击全部不发。因为在这些游戏里点地面不一定是走路
（可能是"选中目标"或"取消"），继续点会表现成"程序在动、角色没动"——比不动更难判断。

## 8. 实测两位玩家的方案

**火炬之光：无限（PC）** —— 全部 `ready`（除地图），可以直接跑：

```
走位 = 点地面(左键)，主攻 = 鼠标右键(按住)，技能 = Q/W/E/R
拾取 = A，交互 = D，返回 = ESC
```

**魔兽世界** —— 5/7 就绪，走位 `partial`、拾取 `unknown`：

```
走位 = WASD + 鼠标视角（不会转视角 → 方向不准）
主攻 = 1(连按)，交互 = 右键点目标，返回 = ESC，地图 = M
拾取 = 未学（魔兽是自动拾取/右键尸体，不该猜一个键）
```

同一套引擎、同一份决策代码，换的是 `scheme.yaml`。这就是"不一棒子打死"。
