# 交付说明（每张截图"该判成什么"）

一行一张。没有这张表，截图只是截图；有了它，就变成 `tools/ref_check.py` 的回归用例。

格式：`文件名  一句话：这是什么界面 + 期望程序怎么做`

填写示例（照这个写，不用管格式整齐）：

```
battle_01.png      战斗，HUD 完整，画面里没有掉落物 → 可以打怪，但不能出现"接近光柱"
battle_02.png      战斗，画面右下偏中有一根金色细光柱 → 应该朝它走，靠近后拾取
map_select_01.png  关卡选择/星图，屏幕上有 7 个发光地图节点 → 绝对不能动，那些不是光柱
backpack_01.png    背包界面 → 绝对不能点，点了会卖装备/洗点
result_01.png      结算界面（"再次挑战"） → 可以点"再次挑战"
```

## 需要额外说清楚的三件事

1. **光柱长什么样**：颜色（金/粉/紫/白）、粗细（大概几个像素宽）、有没有白芯、
   是直的还是带光晕。如果游戏里"地面掉落物"不是光柱而是图标/文字标签，直接说"是图标"，
   我按图标方式做，不会硬套光柱那套阈值。
2. **角色在屏幕哪个位置**：正中央？还是偏下 1/3？走位全靠这个，猜错方向就全反。
3. **交互键**：拾取/确认/ESC 分别是哪个键或点哪里。
