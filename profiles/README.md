# profiles —— 一个游戏一个目录，引擎代码不动

这个目录就是"换游戏"的全部工作量。`autogame/` 里的检测、决策、走位、执行不区分游戏；
区分游戏的只有这里的三样东西：**画面长什么样、哪些界面绝不能动手、目标物在屏幕上是什么样子**。

## 你要做的三步（第三步之后还有一步可选的）

### 1. 丢截图

```
profiles/<游戏id>/inbox/
    battle_01.png       # 正常战斗，HUD 完整
    battle_02.png       # 战斗，掉了一个品质好的东西（有光柱）
    map_select_01.png   # 关卡选择/星图/世界地图
    backpack_01.png     # 背包/角色面板/商店/结算
```

同一个游戏用同一个目录，**每种界面至少 2 张**（不同地图/不同光效，防止我按一张图过拟合）。

### 2. 一句话告诉我"这张该判成什么"

在 `deliveries.md` 里写，或者直接跟我说。格式就一句：

```
battle_01.png     战斗，没有掉落物 → 应该能打怪，但没有"接近光柱"这类指令
battle_02.png     战斗，画面右侧偏下有个金色细光柱 → 应该朝它走
map_select_01.png 异界星图，7 个发光地图节点 → 绝对不能动，那不是光柱
backpack_01.png   背包界面 → 绝对不能点
```

**没有这句话，截图只是截图。** 有这句话，它才变成回归用例——以后我改任何阈值，
`tools/ref_check.py` 都会拿它验一遍，不对就报错。这是我保证"不瞎猜"的唯一手段。

### 2.5 想让它真的会玩：写教学手册

上面这段只说明"这一张图该判成什么"。要让它知道**一类界面怎么认、光柱长什么样、
一局怎么走、哪个键干什么**，写进 `lessons/`，一条命令编译成判据和说明：

```bash
py -3.12 tools/teach.py --profile <id>
```

格式、七种类型、产物见下面「教学手册」一节。写错格式会警告并指出行号，不会静默丢。

### 3. 我跑标定

```bash
# 扫 inbox，逐张出探针分数 + 生成待填台账
py -3.12 tools/profile_init.py --profile tli_phone960

# 按台账核对（strict 不符就 exit 1）
py -3.12 tools/ref_check.py --profile tli_phone960

# 用这个 profile 跑生产
py -3.12 run_server.py --config config.yaml --profile tli_phone960
```

## 自动 / 必须人工，边界在哪

我**不能**凭一张图"看懂"这是什么，因为历史已经证明我会看错（把技能图标角落当成 "Q"，
把星图节点当成光柱，把角色面板下的血球当成在战斗）。所以流程是这样分工的：

| 环节 | 谁做 | 说明 |
|---|---|---|
| 这张图属于哪类界面 | **你** | 一句话，见上面第 2 步 |
| 战斗 HUD 拿哪一块当锚点 | 我做候选，**分数裁决** | 圈出候选 → 对全部真实帧算分数 → 战斗帧 ≥0.6、菜单帧 ≤0.4 才算通过 |
| 光柱颜色/形状阈值 | 我做候选，**分数裁决** | 同上，误报一张就作废 |
| HUD 排除区（哪些矩形不可能是掉落物） | 我做候选，**你眼校** | 页面上的"相机标定"能看框 |
| 角色是否在屏幕中心 | **你** | 一眼的事，我猜错整个走位方向就反了 |
| 交互键位（确认/ESC/拾取） | **你** | 键位没法从画面推 |
| 落地成 profile + 回归用例 | 我 | 你不碰代码 |

一句话总结：**"这是什么"你定，"拿什么像素证据判定"我算，"算得对不对"用你给的答案验。**
中间任何一步没有分数支撑，我不会写进 profile——宁可报"这块标不了"，也不塞一个看起来
合理的阈值进去。

## 三级裁决：认得就自己做，拿不准才问模型

标定解决的是"我认不认得这个画面"。但认得了之后还有一类问题：**认得了，但不知道该干什么**。
这就是三级裁决要处理的事，顺序按代价从低到高：

| 级 | 什么情况走这一级 | 代价 | 输出 |
|---|---|---|---|
| **L0 经验直出** | 这个局面以前验证过，经验库里是 `confirmed` | **0 次模型调用** | 直接执行已验证的动作 |
| **L1 laya** | 拿不准，但系统支持的动作里应该有能用的 | 一次小模型调用（1~3s） | 从**动作清单**里挑一个 |
| **L2 大模型** | L1 说"清单里都不合适"（others） | 一次大模型调用（3~15s） | 一串步骤，每步仍须是清单里的动作 |

三条不能松的约束：

1. **L1 只能从清单里选**，清单就是 `autogame/decision/actions.py` 里那些，
   每一条都对应 FSM 一个真实方法。清单外的动作、带坐标的动作，一律拒绝执行。
2. **L2 也必须翻译回清单**。计划里只要有一步做不到，整条丢弃——不执行残缺计划
   （前一步动了后一步没动，局面会比现在更糟）。
3. **等答案的时候人不能站着**。请求在后台线程，主循环该打怪打怪；真的闲着且有怪，
   会插一个保命动作（`keepalive_after_s`）。

### 经验放在哪

和你的玩法说明放在**同一个目录**（`knowledge/`），不是散在日志里：

```
profiles/<id>/knowledge/
    game.md              # 你写的：界面、掉落物长得像什么、键位、禁忌
    experiences.jsonl    # 机器踩出来的：局面 → 动作 → 结果（一行一条，可读）
```

`game.md` 会被**原样塞进模型上下文**，而且明确告诉模型"与你的经验冲突时以此为准"。
所以你写进去的话优先级最高——这是你唯一能直接给模型下达指令的入口。

`experiences.jsonl` 的条目带状态，**不是记了就生效**：

```
candidate  --验证成功×2-->  confirmed  --再失败×2-->  rejected
candidate  --验证失败×2-->  rejected（保留，作为"别这么做"的反例给模型看）
```

只有 `confirmed` 才能在 L0 直出。这条是防幻觉的关键：模型编一个新做法，第一次只是
`candidate`；真执行过、对账（拾取数涨了/怪少了/回到战斗了）也确认有效，才升 `confirmed`。
否则第二天它会变成"真理"每帧执行，而且你查不出来是谁决定的。

### 不用装模型就能看

```bash
py -3.12 tools/arbiter_demo.py          # 三个场景：认得 / 问 laya / 问大模型并沉淀经验
py -3.12 tools/arbiter_demo.py --scenario c
```

场景 C 会完整演一遍"第一次不认识 → 问 laya → others → 问大模型 → 执行 → 验证 → 下次不再问"。

真实运行时同样的事写进 `logs/arbiter.jsonl`。**默认是 `shadow`**：照常判断、照常记账，
但一条命令都不发。跑一段看它想干什么，确认都对再切 `enforce`。

## 教学手册：怎么写，程序才吃得下

截图 + 一句"这是关卡选择页"能解决"这张图该判成什么"，但解决不了"这类界面怎么认、
光柱到底长什么样、一局怎么走、哪些键干什么"。这些得写下来，写成机器能编译的形式。

放在 `profiles/<id>/lessons/`，一份或多份 `.md`（按文件名顺序编译），图放 `lessons/img/`
或直接引用 `../refs/`。格式就两条：**每段以 `## 类型 · 标题` 开头，段内用 `- 字段: 值`**。
完整样例见 [`_template/lessons/example.md`](_template/lessons/example.md)。

```markdown
## 界面 · 关卡选择（星图）
- 图: img/screen_01.png
- 判定: 反例
- 在: 左上角「‹ 异界」标题块
- 一眼认出: 左上「‹ 异界」标题 + 7 个发光圆形节点
- 该做什么: 不做任何操作
```

`- 框:` 可以不写 —— 见下一节。写了以你为准。

七种类型，各有各的归宿 —— **每一条要么变成判据、要么变成文字、要么变成待办，没有第四种**：

| 类型 | 你写什么 | 变成什么 | 能自动验吗 |
|---|---|---|---|
| `界面` | 图 + 判定（正例/反例） | `labels.json` 台账条目 + 裁锚点的建议 | **能**：门禁结论必须和你写的一致 |
| `物体` | 图 + 框 + 颜色/形状 | 实测像素尺寸、高宽比、主色；与现有阈值比对 | **能**：现有判据检不出你标的这束光柱就直接报 |
| `键位` | `- 拾取: A` | 与 `decision.pickup_key` 等配置核对 | **能**：对不上就报冲突 |
| `流程` | 编号步骤 | 写进 `game.md` 受管块，进模型上下文 | 不能（文字） |
| `禁忌` | 一条条"不要做什么" | 同上，且标成最高优先级 | 不能（文字） |
| `术语` | 表格：我说的 / 标准说法 | `glossary.json`，进模型上下文 | 不能（文字） |
| `（其它）` | — | 跳过并警告，不静默丢 | — |

```bash
py -3.12 tools/teach.py --profile <id>            # 编译 + 核对 + 写产物
py -3.12 tools/teach.py --profile <id> --dry-run  # 只看，不写文件
py -3.12 tools/teach.py --profile <id> --check    # 只核对；有"不一致"就 exit 1
```

产物（全部可重跑，重跑十次结果一样）：

```
knowledge/game.md        <!-- teach:begin --> 块被重写，块外你写的字一个不动
knowledge/glossary.json  黑话对照表
labels.json              界面类条目自动入库（核对通过才 strict=true）
teach/report.md          这轮吃了什么、卡在哪
teach/pending.json       要你补的清单（缺图/缺框/键位冲突/阈值不符）
```

三个判断写死在代码里：**核对不过不许 strict**（条目仍入库，`strict=false` + 原因写在备注里，
缺口可见但不让 CI 变瞎）；**已有条目绝不覆盖**（人的话比生成的更值钱）；**量不到就说量不到**
（没框不编高宽比，没图不编颜色）。

## 文档 → 模板：人说方位，程序量坐标

做一块门禁模板，原本要人干四件事：量坐标、裁图、缩放到基准宽、拿别的图验分数。
四件里没有一件需要人的判断，却全压在写文档的人身上——这就是"进模板难"。

现在这一层由 `tools/teach_crop.py` 接走。**你只需要写"在哪儿、是个什么东西"**：

```markdown
## 界面 · 战斗
- 图: ../refs/combat_01.jpg
- 判定: 正例
- 在: 右下角技能轮盘 + 左下角摇杆
```

```bash
py -3.12 tools/teach_crop.py --profile <id>            # 出模板 + 预览页
py -3.12 tools/teach_crop.py --profile <id> --dry-run  # 只看不写
py -3.12 tools/teach_crop.py --profile <id> --only 星图
py -3.12 tools/teach_crop.py --profile <id> --write-back  # 顺手把量到的框填回手册
```

它做的事，就是人裁锚点时脑子里走的那四步：

| 人怎么想 | 程序怎么算 |
|---|---|
| 我知道它在右下角 | 方位词 → 搜索区域（没写方位就只搜四条边带——UI 都贴边） |
| 我知道它是个圈 | "轮盘/圆/摇杆/图标" → **圆检测**，4 个图标聚成一圈才框整圈 |
| 它得是固定的、别处没有的 | 匹配第二峰（星图 7 个节点长得一样 → 扣分；标题块唯一 → 加分） |
| 别的战斗图上也有、菜单上没有 | 跨图命中 + 误报，两个都是硬阈值 |

**为什么不是"让 AI 看一眼图"**：上面四条全是像素能算的，加个视觉模型只是把工作量
从"量坐标"搬到"审模型"，并没有变少，还多一个说不清理由的黑盒。这里不调模型。

产物：

```
templates/gate_pos_*.png   裁好的模板（1280 宽基准，运行时按实际帧宽缩放）
templates/_index.json      每张模板的来源（哪张图、哪个框），日后能原样重裁
teach/crops/preview.html   原图 + 红框 + 裁出的模板 + 分数，并排放 —— 先看这个
teach/crops/crops.json     机器可读的清单，也是你改框的地方
teach/crops/report.md      结论 + 建议的匹配 ROI + 还缺什么
```

`preview.html` 是这套流程的关键一环：**没有"一眼过目"这一步，前面全是黑箱**。
看着不对有两条路，都不用重跑整个流程：

```bash
# 1) 直接给框（推荐）
py -3.12 tools/teach_crop.py --profile <id> --set "星图=0,0,300,80"

# 2) 改 teach/crops.json 里的 rect，把该条的 "locked" 设成 true，再跑一次
```

`--set` 和 `locked` 都会被记住，以后重跑不再自动搜那一条。手册里的 `- 框:` 优先级更高
（它是文档的一部分，改了立刻生效，不受锁影响）。

**它会主动告诉你不够格的地方**：只有 1 张同类截图时说"没法跨图验证"；一张反例都没有
时说"验证不了会不会误命中"；检出不了你标的这束光柱时，把差多少像素列出来。
这些都不许悄悄凑合——一个"看起来合理"的模板比没有模板更危险。

## 二次进化：材料进来，配方出去，学坏了能退

> 这一章讲**配方**（设备自己学）。引擎（代码）是另一件事：不能改，但能整包升级，
> 见 [docs/升级引擎.md](../docs/升级引擎.md)。两边各有各的"退回"，互不牵连。

装到设备上之后，日常**不用敲命令**：材料一变它就自己学（见下面「持续学习」）。
只有两件事需要动手：

```bash
py -3.12 tools/evolve.py --profile <id>              # 服务没起 / 想立刻学一次
py -3.12 tools/evolve.py --profile <id> --rollback   # 学坏了，退回上一代
```

### 为什么"生成代码"其实是"生成配方"

你想要的"针对我这个游戏再生成一些代码"，如果真的是让模型去改 `autogame/` 里的
Python，在 RK3566 上会有一个致命后果：改坏了没有 git、没有编译器、没有 shell 能救回来。
而且"模型改的这行是什么意思"永远说不清。

所以进化的是**配方**，不是引擎：

| 产物 | 形态 | 谁执行 | 错了会怎样 |
|---|---|---|---|
| `rules.yaml` | 数据（条件 → 动作） | 引擎逐帧求值 | 这一条不生效，日志里有原因 |
| `templates/*.png` | 图片 | 模板匹配 | 分数掉，回归会拦 |
| `knowledge/` | 文字 | 进模型的 prompt | 模型读了会参考，不硬编码 |
| `gen.yaml` + `active` | 指针 | 加载时读 | 回滚就是改一行指针 |

`rules.yaml` 长这样，事实和动作都是白名单，写别的名字会被整份拒绝：

```yaml
rules:
  - id: r_pick_when_pillar
    when:
      all:
        - {fact: pillars, op: ">=", value: 1}
        - {fact: in_game, op: "==", value: true}
    then: {action: pickup}
    why: 手册里写"看到光柱就走过去捡"
```

规则在裁决链里是 **L0.5**：比问模型早（1.5 秒 vs 8 秒），但只在 FSM 停手够久时接上。
这是"补位"不是"夺权"——规则写错时如果它能长期压过 FSM，整个角色行为会跑偏，
而且很难从日志看出是谁干的。

### 一条命令背后的五件事

1. **材料体检**：正例 ≥2 张不同帧、反例 ≥2 张、标答 ≥3 条（台账 strict 或手册里带图的
   「界面」条目，两者都算）。不够就**不出代**，只告诉你缺什么。
2. **编译手册**：`teach.py` 把文字分成"可验证判据 / 进 prompt 的文字 / 待办"三种归宿，
   写进这一代的 `knowledge/`。
3. **规则草稿**（可选模型）：把「流程 / 禁忌」条目翻成规则，逐条过 DSL 校验。
   模型不通就跳过，这一代照样能出——只是没有硬规则。
4. **回归**：拿台账（或手册合成的临时标答）跑一遍检测器 + FSM，出通过数。
5. **过闸门才上线**：新代的通过数不能比当前这代少，且不能有新增失败。差一条就留在
   `rejected` 状态，并写清是哪条退化了。**宁可停在原地，也不要为了认一张新图把已经对的画面搞错。**

### 三条不会松动的规矩

- **材料没变不出新代**。指纹一样必然出不了新代，页面会直接说明"材料没有新东西"。
  不这么做，跑十次就是十代，回滚列表很快变成垃圾场。
- **没有标答的材料只能进 prompt，不能进规则**。因为规则命中就直接派动作、不问模型，
  错了没人兜；而 prompt 里的文字错了，模型还有机会不采信。
- **第一代必须台账全过才算基线**。第一代就有不符，说明手册或模板本来有问题，
  这时候上线等于把问题固化成"基线"，以后再也看不出退化。

### 持续学习：不用记得点按钮

装到设备上之后，材料不是一次给齐的，是**一点点长出来的**，而且经常推翻自己之前说的：

    玩了两把，结算界面不认识 → 截两张图丢进来
    过几天发现背包要按 B → 补一句
    又发现"看到光柱就走过去"说得不准 → 改成"先看清是不是自己的光柱"

这种节奏下"点一下学一遍"有两个毛病：人得记得点；点的时候常常材料还没写完。
所以引擎里有一个常驻的守望者（`autogame/learner.py`），每 15 秒看一眼材料，
该学就学。它只决定**什么时候学**，不决定**学了算不算数**——算不算数仍然只看回归。

| 它不会做的事 | 为什么 |
|---|---|
| 你还在写就动手 | 材料的最后修改距今不足 `quiet_s`（默认 45s）就等。连着截五张图不该学五次半成品 |
| 机器人在跑的时候学 | 换代会让正在执行的动作失去依据（模板换了、规则换了，打了一半的目标没了）。停手才学 |
| 同一份材料反复重试 | 回归没过说明是材料问题，不是运气。默认只试 1 次；改了材料（指纹变）才重新给机会 |
| 半分钟学一代 | 两代之间至少隔 `min_gap_s`（默认 180s）。学一次要几十秒 CPU，和采图抢核画面会卡 |

`config.yaml` 里可以调：

```yaml
learner:
  enabled: true        # 页面上的开关会覆盖这里
  interval_s: 15       # 多久看一眼材料
  quiet_s: 45          # 材料安静多久才动手
  min_gap_s: 180       # 两代之间至少隔多久
  max_tries: 1         # 同一批材料最多自动试几次
  use_model: true      # 关掉则只编手册、不起草规则
```

**每一代都记着"它吃了什么、长了什么"**（`materials.json` + `delta.json`），
所以页面能说出人话，而不是一个指纹：

    gen-007  在用  台账 3/3  材料 改1  知识 +2
    改了 lessons/tli.md；新增认识：**背包满了**、**补充 2026-11-19 10:49**

**学坏了怎么知道**：被拒的那一代会记住原因，页面状态条直接显示"这批材料上次没通过：
通过数从 3 跌到 2，新增失败 refs/xx.png"，并且不再自动重试。想硬跑一次点「现在学」——
手动不受自动那套节奏约束。

**它说没学到，也是信息**：手册改了、但知识一条没增没减，页面会红字提示
"多半是格式没被认出来"。这比"看起来学会其实没听懂"诚实得多。

### 新的理解从哪进来

页面「进化」页有一张「补一条经验」：问两个问题——**什么时候用得上**、**该怎么做**——
写完直接进手册（`## 流程 · 补充 <时间>` + `- 一眼认出:` / `- 该做什么:`），
不用懂 markdown，也不用再点学习：材料变了，上面那套自己接手。

为什么不给一个自由文本框：解析器不认的自由文本，写进去也学不到，比不给入口更糟。
要加界面/物体的**图**，还是得 `scp` 一张进 `refs/` 再在手册里写 `- 图:` + `- 判定:`。

### 它会告诉你缺什么（自我纠正）

`py -3.12 tools/evolve.py --profile <id> --wanted`，或者在页面「进化」页看第二张卡片。
信号来自运行日志，不是模型瞎猜：

| 日志信号 | 它的判断 | 让你补什么 |
|---|---|---|
| supervisor 判 panic | 这个画面完全不认识 | 截一张当时的样子，说清是哪个界面 |
| supervisor 判 hold | 拿不准该不该动 | 那个界面的**反例图** |
| supervisor 判 takeover | 动作没生效 | 该状态截图 + 手册写清按什么键 |
| arbiter 走 L2 | 规则和经验都覆盖不到 | 把这类情况写成「流程」条目 |

这是"自我纠正"唯一诚实的形态：系统报告自己的不确定处，向你要针对性样本。
模型自己改参数不叫纠正，叫漂移。

### 页面在哪

`/settings` → 「进化」页：当前第几代、**它自己有没有在学**（状态条 + 自动开关）、
待学清单（你改了哪个文件它还没看）、材料体检逐项结果、它认为缺什么、代数记录，
以及「补一条经验」「现在学」「退回上一代」。

状态条就几种，看颜色和那句话就够：

| 状态 | 意思 |
|---|---|
| 材料没有新东西 | 学完了，等你补材料 |
| 材料刚动过，还有 N 秒 | 防抖中，它在等你写完 |
| 机器人正在跑 | 停手就学，不在它手里换配方 |
| 材料还不够 | 缺什么列在下面，补了自动学 |
| 这批材料上次没通过 | 不自动重试了；改材料或点「现在学」 |
| 刚学过，N 秒后再看 | 两代之间留了间隔 |

### 装到 RK3566 的实际顺序

```bash
# 1. 先跑通基础机器人（不带游戏知识也能跑，只是会频繁停手）
py -3.12 run_server.py --port 8765

# 2. 手机/电脑打开 http://<设备IP>:8765/settings
#    「AI 顾问」里配好模型：laya 填本机 ollama 的 qwen2.5:1.5b 或 3b，
#    planner 有网时填云端（清单里都没有才会用，频率很低）

# 3. 往 profiles/<id>/inbox/ 丢截图，按 _template/lessons/example.md 写手册
#    refs/ 放标定用的图，lessons/ 写玩法描述

# 4. 第一次：量模板 + 编译 + 出基线代
py -3.12 tools/teach_crop.py --profile <id>
py -3.12 tools/teach.py --profile <id>
py -3.12 tools/evolve.py --profile <id>

# 5. 之后：不用再跑。补了截图/描述，服务自己会学（页面能看到它在等什么）
#    没起服务、或者想立刻学一次：py -3.12 tools/evolve.py --profile <id>
```

服务没在跑的时候（比如你在开发机上折腾），持续学习当然不会自己动 ——
它跑在 `run_server.py` 的进程里。这时候用命令行那一条，效果一样。

设备上没有开发环境也没关系：`evolve` 只读写 `profiles/<id>/`，不碰 `autogame/` 的代码。

## 指令组：教会它一件事，然后用一句话叫它做

引擎本来就会走位、捡东西、脱困、点「再次挑战」—— 它不知道的是**自己在做哪个任务**。
中间缺的不是能力，是一个名字。指令组补的就是这个：一段有名字的步骤，喊一声就跑整套。

### 怎么写

在手册里加一段，和写「界面」「流程」一样：

```markdown
## 指令组 · 刷k7

- 喊作: 刷k7、打k7、k7、搬砖
- 起点: 异界星图
1. 在星图点「K7节点」，进图
2. 清怪，沿途捡掉落
3. 打完 Boss 出结算
4. 点「再次挑战」，回到第 2 步
```

`喊作` 是你可能说的叫法（越口语越好，程序会做全角/空格/大小写的归一）。
`起点` 是这一组该从哪一屏开始跑。中间的步骤就是编号列表，程序只认四种动作：

| 你写的 | 程序理解的 | 举例 |
|---|---|---|
| 点「X」 | 点击屏幕上的 X（需要模板或内置能力） | 点「K7节点」 |
| 按 A | 按一次键 | 按 ESC |
| 清怪 / 捡 / 刷 / 打完 | 交给引擎自由跑，直到你写的那个界面出现 | 清怪，沿途捡掉落 |
| 等到 X | 什么都不做，等这个界面出现 | 等到结算 |

不写「直到」也行：句子末尾提到的界面名会被当成完成条件（"打完 Boss 出结算"→ 结算）。
连着的两句「清怪」「打完 Boss 出结算」会被合成一步 —— 它们本来就是一件事的两个说法。

### 两种不该让你动手的情况

- **引擎已经会的事不要求模板**。「再次挑战」是每帧扫出来的按钮（`SceneState.rechallenge`），
  所以 `点「再次挑战」` 直接可用。逼你为它裁一张图是倒退。
- **缺什么就说缺什么，而且不跑**。点了「开始」但缺模板时，它一个动作都不发，只在页面上写
  "第 1 步要点的「K7」没有对应模板"。缺模板硬跑的结局是每帧点空、几十秒后报一次超时，
  比不做更糟。

### 为什么"进了另一组就会把上一组忘了"不会发生

因为这取决于**认识存在哪**，而不是取决于程序记性好坏。三层分得很死：

```
世界层 groups/_world.json     术语、界面、物体、键位、禁忌 —— 全游戏唯一一份
组层   groups/<组名>.yaml      只是"步骤 + 对世界层的引用"，一组一文件
配方层 evolve/gen-XXX/        每代自动生成的 rules.yaml + templates
```

新教一组只能往世界层**添**，不能自带一套界面表。所以：

- 组之间不会互相覆盖（一组一个文件，学习只重写自己那份）
- 手册被改小时，世界层只增不删 —— 你删掉一段旧描述，不会让另一组突然不认得战斗画面
- 同一个界面被写出两种判定（一会儿正例一会儿反例）时，记进 `_conflicts.json` 并在页面上报，
  采用你最后写的那句。**不静默覆盖**：门禁忽正忽反是会真的乱杀人的
- 手册里删掉一整组，**文件也不删** —— 只记进 `_orphans.json` 标成"手册里没了"。
  改一句话就让一个能跑的任务凭空消失，是最让人不信任的行为。要真删，在页面上点。

### 怎么喊

页面「指令」页：输入框打一句，点**只听**看它认成哪一组、为什么这么认，再点**开始**；
或者直接点组卡上的「试」。命令行/接口走 `POST /api/command {"text": "刷k7"}`。

**喊一句就是让它开始干活**：引擎停在暂停态时会被自动恢复，不用再去别的页面点一次「开始」。
唯一的例外是急停（PANIC）——那是事故现场，得人看过再解。反过来，页面上那个「停」是
**真的停**：任务和引擎一起停下，不是"任务停、人走了它还在自由刷"。

匹配分四路，可信度递减：一字不差 → 你的话里含着它 → 按术语表换算后再比（说"搬砖"能对上
"刷图"） → 打错一个字。**分不清就不猜**：两组分数太接近时返回候选让你选，"来一把"这种
认不准的话一个动作都不发。猜错一次不是多点一下，是好几分钟的错误操作。

### 组和配方是什么关系

配方（`rules.yaml`）是条件反射：看到光柱就捡、看到结算就点再次挑战。组是任务顺序：
先点节点、再打一圈、再点再来一局。两者叠加生效 —— 组管"现在该干哪一段"，
配方管"这一段里遇到这种情况怎么反应"。所以组不会覆盖规则，规则也不会打乱组的顺序。

回退配方（「退回上一代」）不影响组：组是数据，存在 `groups/` 里，不进代。

## 目录约定

```
profiles/<id>/
    profile.yaml      # 元信息 + 对这个游戏的 config 覆盖（与 config.yaml 同构）
    lessons/          # 你写的图文教程（*.md + img/），teach 从这里编译
    templates/        # gate_pos_*.png 正向锚点 / gate_neg_*.png 反例 / _index.json
    labels.json       # 人工标答台账（ref_check 逐字段核对）
    knowledge/        # game.md（人写的）+ glossary.json（黑话）+ experiences.jsonl（经验）
    teach/            # 编译报告与待办（report.md / pending.json，可随时删）
    evolve/           # 二次进化：gen-XXX/ 每代一个目录 + active 指针 + history.jsonl
    groups/           # 指令组：一组一个 yaml + _world.json（所有组共用的世界层）
    inbox/            # 你丢进来的新截图
    refs/             # 标定完成的截图存档（inbox 里清空后挪这儿）
    deliveries.md     # 你写的"这张该判成什么"
```

`templates/_index.json` 记录每张模板"是按多宽的帧裁的"。默认路径
（`tools/make_template.py`）会把裁块统一缩放存成 1280 宽，这时不用管它；
只有你手工裁了张原生尺寸的图（比如直接从 960 录屏截一块没缩放），才需要在这里声明
`base_width`，否则会被按 1280 反推缩放，分数掉到噪声水平。

顺带澄清一个容易混的点：**模板跨分辨率大致能用，跨游戏基本不能**。把技能栏模板放在
同一游戏的另一分辨率上，分数是 0.9→0.7 这种衰减；放到另一个游戏上是 0.25——那不是
缩放错了，是两块 HUD 本来就长得不一样。所以每个游戏都要有自己的 `gate_pos_*.png`，
没有捷径。

## 一个真实标定的完整过程（tli_phone960）

留在这里当范例，照着做就行：

```bash
# 1) 探针：看每张图的分数、列出所有"像光柱"的色块（含坐标和高宽比）
py -3.12 tools/profile_init.py --profile tli_phone960

# 2) 先做反例（门禁反例优先，顺序反了会让菜单直接放行）
py -3.12 tools/make_template.py --src profiles/tli_phone960/refs/tli_nether_map_01.jpg \
    --rect 8,2,205,55 --out profiles/tli_phone960/templates/gate_neg_example.png \
    --check "profiles/tli_phone960/refs/tli_nether*.jpg"

# 3) 再做正例。手机端技能在右下角，必须带 --roi，否则默认的"底部 35%"会裁掉一半
py -3.12 tools/make_template.py --src profiles/tli_phone960/refs/tli_combat_01.jpg \
    --rect 640,255,900,390 --roi 600,235,960,432 \
    --out profiles/tli_phone960/templates/gate_pos_skillwheel.png \
    --check "profiles/tli_phone960/refs/tli_combat_0*.jpg" \
    --against "profiles/tli_phone960/refs/tli_nether*.jpg"

# 4) 回归
py -3.12 tools/ref_check.py --profile tli_phone960
```

第 3 步实测：自匹配 0.993、另一张战斗帧 0.883、星图 0.281。三条都过才写进 templates/。

## 常见坑

- **正例没轮上 ROI 就下结论"模板不管用"**：默认 ROI 是底部 35% 全宽，那是 PC ARPG
  技能栏横在底部的假设。手机端技能在右下角，不传 `--roi` 分数会从 0.99 掉到 0.3。
- **把 `template_base_width` 改成录制分辨率**：模板是 1280 归一化存储的，改成 960 会
  让反例从 1.00 掉到 0.41，表现是"菜单拦不住"，但看起来像"模板失效"。
- **先做正例再做反例**：门禁反例优先，正例先上就等于给菜单发了通行证。
- **裁到动态元素**：技能图标会随冷却变灰、光环会闪。要裁位置固定且外观稳定的
  部件（边框、外圈、标题栏），分数不稳就是裁错了。
